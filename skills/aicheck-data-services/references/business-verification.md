# 按业务问题开展专项求证

每次使用本 Skill 均以设计—施工一致性、证明文件、人员资格和焊材适配为思考主线。仅 OCR、标准查询、证件登记查询仍按用户范围执行，并说明本次数据支持哪项求证、其余尚未核验。

## 问题与核查关系

下表提炼项目《业务节点描述 v3》的关联思路。节点号用于解释检查来源，不是节点整体审查结论，也不要求用户提供节点绑定。本发布包不依赖仓库文档或节点规则接口；具体限值与覆盖关系仍须核实适用标准原文。

| 用户问题 | 应比较的关系 | 节点参考 |
|---|---|---|
| 焊工能否焊这个焊口 | 人员身份、资格项目、有效期与实际作业方法、位置、尺寸、日期 | R24，联动 R25 |
| 建设材料是否满足设计 | 母材或元件牌号、规格、标准、交货状态及特殊要求与设计文件 | R16，联动 R08、R09 |
| 焊材是否选对 | 焊材型号、类别与母材组别、WPS、设计要求 | R26，联动 R25 |
| 工艺是否适用于该处 | PQR 支撑范围、WPS 声明范围与管线/焊口条件 | R25 |
| 成分或性能是否达标 | 对应批次的实测值与已核实标准版本、产品形态、型号及适用条件 | R16、R26 |
| 证明书是否证明现场用料 | 炉批或产品编号在证明书、实物/验收记录、领用及施焊记录之间的对应 | R16、R26，相关施工记录 |

## 必须交代的业务关系

专项求证按以下关系组织，不能仅按已成功调用的接口选择结论：

| 关系 | 核验内容 |
|---|---|
| 设计 ↔ 施工 | 当前有效设计及批准变更规定的工艺、母材与实际 WPS、材料和施工参数逐项比较；工艺与材料分别表达 |
| 工艺、材料 ↔ 证明文件 | PQR 是否支撑 WPS 及实际工况；材料成分、性能是否满足适用国家标准、设计引用标准及特殊要求；文件是否对应实际对象 |
| 人员资格 ↔ 设计工艺及实际作业 | 身份、资格项目、方法、位置、材料/尺寸范围及作业日期覆盖；实际工艺偏离设计时同时指出偏离，不能仅因人员覆盖实际作业就认定满足设计 |
| 焊材 ↔ 设计、母材与工艺 | 选用型号、组别、批次及实际使用关联；区分焊丝本体与熔敷金属等试验对象，核实成分、性能及适用限值 |
| 证明文件 ↔ 来源与现场对象 | 分别核实人员证书、材料/焊材质量证明、工艺评定的来源、编号、签发主体及适用对象；无可用查询渠道时保留未核实状态 |

用户限定单项时只对该项执行，标明其余未核验；综合求证须覆盖上述关系，缺资料写“证据不足”，无适用对象说明原因。缺少实际记录时限定为拟用方案，不能把设计值当实际值。

## 证明文件真实性分层求证

分别记录以下证据，不能相互替代：

- **指标符合性**：可靠读出的材料/焊材成分、性能与适用标准原文逐项比较；满足标准不等于文件真实，也不证明该批已用于现场。
- **来源真实性**：根据可用的官方登记、签发单位核验、可验证签名或原始签发记录核对身份、编号和内容。记录渠道、核验时间及实际返回的范围；证书登记服务不能当作任意材料证明书或 PQR 的验真服务。
- **现场对应性**：文件编号、炉批、实物标识、验收及领用/施焊记录能否形成同一对象的证据链。真文件也可能对应其他批次。

OCR、印章图像、版式相似、内部数据自洽或指标达标，均不能独立证明真实性。缺乏来源核验时直写“指标已核对，来源真实性尚未核实”；未检出或服务失败不能认定伪造。出现可靠矛盾时说明矛盾及影响，需进一步确认时不要直接定性为伪证。

## 建立对象关联

1. 确定本次问题、对象和时间范围。以焊口、管线、材料批次或明确人员为单位；不把多批材料或多人合并为一个“通过”。
2. 建立关联记录：对象标识、人员、母材炉批、焊材批次、WPS、PQR、设计文件版本、作业日期；每条关系保留证据位置，并标记“已证实/仅计划/未建立/存在冲突”。
3. 以文件中明确的焊口号、炉批号、人员记录、工艺引用编号等关联。名称相似、同一文件夹、同一项目不能单独证明对应；未绑定节点的资料照常读取。
4. 无施焊记录时仍可核对设计与拟用方案，但写明“拟用方案适配”，不声称证明实际施工。没有设计资料时可核对已明确产品标准的指标，不能推断满足设计。
5. 同一对象多版本或多个冲突取值并列保留，不能自动采用较有利值。

## 逐维度求证

每项记录：问题、对象、比较维度、实际值及原文、要求值及原文、适用条件、关联状态、比较结果、限制与补充动作。

对成分、性能与资格范围，按 [匹配方法](matching.md) 核对标准版本、组别、尺寸与适用条件。标准全文未取得、关键 OCR 数字不可靠或技术等效尚未确认时，不给确定的达标/不达标结论。材料指标达标与实际使用追溯分别判断。

结论只使用“匹配、不匹配、证据不足、需人工确认”。明确不匹配的维度不得被其他缺项掩盖；同时保留未完成维度。例如有效期明确不覆盖但厚度未知，应分别写“日期不匹配”和“厚度覆盖证据不足”。官方登记未检出、OCR 未识别到、工具调用失败均不自动等于业务不匹配。

## 汇总与去重

按 [输出约定](output.md) 先回答用户原问题。摘要应与明细一致：存在明确不匹配，先点名对象和失败维度；没有明确不匹配但仍有关键缺项，写“尚不能确认匹配”；全部已核查维度均匹配时仍限定对象、期间和本次范围。

同一资料缺失影响多项结论时，仅列一条补充动作，关联多个问题编号，说明补充后能够解决什么。勿把同一缺口按多个节点重复报警，不计算无依据的综合得分或合格率。
