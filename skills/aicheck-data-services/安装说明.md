# AIcheck 数据服务 · 远程版 2.3.1

无需安装 Python，无需填写脚本路径或资料目录。

1. 在 WorkBuddy 导入本 Skill 发布包。
2. 打开「专家·技能·连接器 → 连接器 → 自定义连接器 → 配置 MCP」。合并随包 `mcp.workbuddy.json`，保留已有连接器。新配置替换旧 `aicheck-data-services` 的整个条目，不保留 stdio 的 command、args、env。
3. 保存、启用并信任连接器；必要时新建对话。

```json
{
  "mcpServers": {
    "aicheck-data-services": {
      "type": "streamable-http",
      "url": "http://39.108.65.148:8081/api/mcp/data-services",
      "disabled": false
    }
  }
}
```

当前为内部测试服务，无需令牌。这里是 MCP 地址，不能替换成网站首页或旧 stdio 命令。

## 验收

向 WorkBuddy 发送：

> 使用 aicheck-data-services，实际调用 aicheck_connection，参数为 {}。然后检索 GB/T 39280-2020 并读取返回 fileId 的第7物理页，报告真实状态和错误码，不判断工程符合性。

OCR 测试时再指定一个 PDF/PNG/JPEG 文件：

> 使用 aicheck-data-services 对这份文件进行 OCR。先取得临时上传地址，再使用本机文件上传能力将原件 PUT 上传，取得 jobId 后查询状态及第1页结果。若 MinerU 排队超时并切换千问，继续查询同一个 jobId，报告实际引擎、识别结果与未完成项。不要把“取得上传地址”写成“识别成功”。

上传地址15分钟有效，文件最大100MB。远程MCP不能直接读取电脑文件；WorkBuddy需要有读取用户选定文件并发起上传的工具权限，平台要求的权限仍需正常处理。不会因此要求用户安装本 Skill 专用 Python 脚本。

## 常见问题

- **只看到旧工具或 filePath 参数**：连接器仍使用旧 stdio 配置；替换整个条目，重新加载并信任。远程 ocr_submit 使用 fileName、requestId。
- **未连接**：确认类型为 streamable-http，URL完整，连接器已启用/信任。Skill导入与MCP连接是两个步骤。
- **401/403**：联系管理员确认测试开关或正式凭据配置。
- **拿到地址但无法上传**：检查宿主是否有文件/终端上传能力；仅聊天工具无法让服务器读取本机路径。不要声称OCR已完成。
- **MinerU 排队 / 已切换千问**：后台默认连续排队 60 秒后自动切换，继续用原 jobId 查询，不重新上传；这是停止本系统等待，并不表示官方任务已取消。
- **上传超时**：保留requestId和原URL，最多用原文件重试一次，避免重复处理。

文件会进入配置的后台及 MinerU 服务，排队超时后还会发送至阿里云千问 OCR 服务，按服务端策略留存。内部测试使用共享OCR身份，测试人员可读取该身份的独立任务；没有个人隔离或自动到期删除承诺。不输出工程整体合格结论。

2.1 版可在 OCR 提交时指定资料 Profile，返回最终加工结果及处理来源、全文质量和未定位字段。更新 Skill 后重载连接器或新建对话以刷新工具定义，继续使用同一个远程 URL；已有旧结果不会自动重新识别，缺少处理记录时会明确标记。

2.2.0 更新了自动切换与结果解读说明。已经使用远程 MCP 的用户只需更新 Skill 并新建对话，无须修改连接器地址或安装 Python；服务端自动切换能力不依赖重新导入才生效。
