# AIcheck OCR

安装或连接异常时读取 [平台配置](references/platform-setup.md)。本 Skill 配合独立 stdio MCP 使用，运行机器必须有 AIcheck 项目及后端 Python 依赖；仅导入说明文件不等于服务已连接。

1. 调用 `aicheck_ocr_connection({})` 检查引擎、允许读取目录和 profile。配置检查通过不等于实际 OCR 成功。
2. 对用户指定的资料调用 `aicheck_ocr_start`，提供绝对 `filePath` 和明确的 `engine`。`mineru` 上传文件给配置的 MinerU 服务；`runtime` 遵循项目配置，本地文本提取或千问识别，可能发送页面到官方服务。遵循用户已有处理授权，不为每页重复询问；用户要求仅本地时，不调用可能外发的引擎。不得自动切换供应商重试。
3. 保存返回的 `taskId`，间隔查询 `aicheck_ocr_result`，不要重复提交同一文件。终态为 `completed`、`partial`、`failed`；遇失败报告原始错误码，一次修正后再尝试，避免无限重试。
4. 通过 `pageNo` 读取原件物理页（从 1 起），或读取返回的本地 `resultJson`、`textMarkdown`；MinerU 还保留原始结果 ZIP。检查 coverage、quality、表格及关键字段，保留文件名、SHA-256、页码和可用坐标。

## 识别与审查的边界

- 本工具不创建工程、资料库或审查记录；任务与结果保存在本机，供应商及旧本地引擎可能留存缓存。不宣称零留存。
- 识别完成不是工程符合。正文、字段、表格、印章与签名仅是识别线索；印章检测不代表章中文字已读出或真实性已验证。
- 缺失文字、空页、坐标为 null、表格错列、跨页关系不清，必须标记待核对，不能据此判定资料未提供或不符合。
- 日期、证件编号、压力/厚度、单位、小数点、否定词和表格行列关系影响结论时，对照原页；工具 coverage 只证明提取到内容，不保证准确率。
- 与监检 Skill 联用时，把 OCR 结果作为本地证据交给审查流程；标准查询与证件核实继续由审查 MCP 负责。

向用户返回：文件名、引擎、执行状态、识别页数/总页数、未确认页面、结果链接及需要对照的关键内容。不输出密钥、签名下载地址或原始请求日志。
