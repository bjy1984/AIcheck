# R11-01 施工方案簽批記錄專用判定

## 已接通

沿用 evaluate_construction_plan，新增 construction_plan_approval 專用 profile 分流，通用既有 profile 行為保持。AC-R11-01 改讀 r11.approval，生成來源與 YAML、tools規劃同步更新，沒有新增 API 或付費任務。

新增三種明確來源表：construction_approval_context、construction_approval_signatures、construction_owner_approval；來源經既有選定版本／工程／租戶、頁碼範圍、唯一解析、置信度和證據門檻後進入工具。與 R11 參數比較獨立組裝，不因缺少參數表重新猜簽批資料。

專用工具檢查一份明確聲明的施工方案版本與簽批批次：

- 編制、審核、審批各角色唯一，有具來源的 signerName 與 signatureStatus。present 才表示記錄載明有簽字，absent 為明確缺簽；缺角色／重複／不明保持不足。
- 簽字證據必須屬於指定方案版本，projectId／ownerOrganizationId／approvalCycleId 一致。不同版本、工程或批次不串用。
- 建設單位回覆只讀同作用範圍的明確 approved／rejected，pending 或缺少回覆保持不足。沒有回覆不推斷已批准，也不抹掉已明示缺簽。
- 所選頁面不完整時，文件記錄相符不當成完整通過；已知缺簽／拒絕回覆保留。多方案清單未實作，工具只接受有来源声明的單一方案集合，不宣稱全工程方案覆蓋。

## 未完成能力與發布限制

本工具 scope=documented_plan_signatures_and_owner_reply_only，wholeRuleAcceptance=not_evaluated、evidenceVerified=false。這不是簽名真偽、簽字權限、建設單位外部身份、批准有效期或時間先後的核驗。

AC-R11-01 的 parameters.pendingCapabilities 明確保留 signature_authenticity_and_authority、owner_reply_validity_and_timing。因此專用工具可對文件記錄輸出 passed，但原子結果仍為 evidence_insufficient；已明確拒絕批復等問題仍為 failed。前端按兩類顯示下一步人工核對事項，不提供虛假的人工核验背書。

本批為標準化來源表／合成固定版本驗收；真實簽章、批復文件的 OCR 適配、時間條件、外部身份和多方案清單尚未完成。不偽造不適用條件；本強制簽批路徑目前没有可驗證的 not_applicable 案例。
