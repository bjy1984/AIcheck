# R39來源門檻與不適用分支修正（Lab）

## 問題與修正

原R39事實builder雖保存來源可信度供後續證據門禁使用，但單獨執行新專用工具時，可在低可信度或來源已有衝突時返回子檢查通過。首次應用工具亦在讀取驗證記錄前返回非首次應用不適用，可能略過單筆跨事件記錄。

現在builder返回前分別對firstUseValidation、approvalChain與documentContent的實際來源資料列執行初步來源門檻，重用validate_evidence_grounding。每一類只核對其相關表，不因另一類工具來源有問題而刪除本類可用输入。錯誤輸入移除，但保留sourceRecords、sourceIssues及sourceValidation，沒有隱藏資料。

## 來源門檻

- 來源可信度必須為0至1內實際數字，拒絕bool、字串、NaN、無限值及越界值；避免非有限數值進入共用Decimal比較造成異常。
- conflicted未提供沿用「未收到明確衝突」語義；若提供，必須為布林且false，true及非布林均阻擋。
- 本批初步可信度下限為0.75，沿用目前R39證據門檻。實際原子執行仍須採用凍結規則的證據門禁；此初步檢查不得取代更嚴格的規則要求。
- 共用門檻核對引用ID、頁碼／位置與可信度／衝突；R39子工具另要求實際摘錄。通過不等於原文語義支持或人工核實，evidenceVerified仍false。
- 顯式conflicted=false在檢查後作為來源元資料移除，不再誤當批准流程中的未知業務要求。其他未知業務條件仍保留供專用工具拒絕。

## 判定契約更新

首次應用工具版本改為r39-first-use-validation-occurrence-v2，增加必需頂層projectId並與scope.projectId核對，接上既有runtime工程限制。已提供的validation須先通過身份和引用檢查，再判斷是否首次應用。非首次應用仍不要求新增驗證記錄，但不能帶入另一事件或無效引用而被忽略。

內容工具版本改為r39-nbt47013-common-document-content-v2。已提供的contentInventory及field身份、未知／重複fieldId在不適用分支前檢查；不適用仍可不提供內容清單，不能用該分支掩蓋錯範圍資料。

沒有修改歷史結果、R39正式原子綁定、工具發布狀態或生產部署。技術要求、完整清單及原文語義驗收仍待完成。
