# 交接核驗跨 HTTP 程序驗收

兩個 loopback uvicorn 獨立程序使用同一個臨時 PostgreSQL 資料庫。測試使用專用測試資料庫權限，每次建立 UUID 資料庫，結束後停止程序並刪除該測試資料庫；不讀寫使用者本機工程 API 或生產服務。

首次實測：同步提交僅一筆成功，但失敗方隨後 GET 詳情看不到核驗歷史，證明原有節流快取不足以支援核驗後即時確認。

修復：交接清單與詳情沿用 `_refresh_dependency_state` 嚴格更新交接、來源任務、文件與修正等資料。更新失敗返回503；保留讀取前後的授權檢查。沒有變更判定碼、核驗歷史或工具發布狀態。

覆蓋：

- 兩端先讀取相同舊版本，透過同步屏障同時送出不同冪等鍵的核驗。
- 僅一筆保存，另一筆必須為40906持久化衝突，或40001且明確為核驗版本已變；不接受500作為通過。
- 兩端清單／詳情均看到同一歷史；新版本更正後兩端一致。
- 資料庫上游來源變動後兩端顯示過期，保留全部核驗歷史。
- 停止兩個程序，啟動新程序後從同一資料庫還原歷史與過期狀態。
- 審查快照僅允許測試明確寫入的來源雜湊變更；AI 任務數及内容保持原狀。
- 清單與詳情的資料庫刷新失敗返回503，不用快取冒充最新狀態。

驗證：75條交接相關回歸通過、0跳過；重啟與明確衝突碼的最終專項1條通過、0跳過（62.89秒），見同目錄日誌。Ruff 289/289、monolith 基線及 diff 檢查通過。

測試檔：`backend/tests/test_review_handoff_http_postgres.py`、`backend/tests/test_review_handoff_node_statuses.py`。在 backend 設定專用 `AICHECK_TEST_POSTGRES_URL` 後執行 `python -m pytest tests/test_review_handoff_http_postgres.py -q`。

限制：合成工程、開發身份頭、app lifespan 關閉並手動配置測試持久化；不是登入、完整服務啟動或真人案件驗收。仍需補工作程序提交結果時來源同時變動的交易邊界。整體約60%，不宣稱90%。
