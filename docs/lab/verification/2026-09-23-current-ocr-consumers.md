# 冻结审查只读取当前 OCR 尝试（2026-09-23）

七项目快照发现同一文件版本可能有多次 OCR。前一批已修节点 1／12／13、R24–R34
及 Jev 输入；本批逐一核对其余直接调用 `selected_parse_results` 的正式审查读取方。
原函数保留历史兼容接口，新 `current_selected_parse_results` 先执行原来的工程、版本、
页码及人工修正规则，再按 OCR 完成／更新时间选每版最新尝试。无法用时间区分的
同版多条记录仍视为歧义；最新明确失败时不回退旧成功。`needs_human_review` 质量
状态不等于整份 OCR 失败，R39 等规则仍能读取已定位内容并自行检查缺页。

| 读取方 | 本批处理 | 保留的边界 |
|---|---|---|
| R14／R15、材料事实共用读取器 | 每个版本只构建当前可用 OCR 的报告、证照和材料记录 | 真正不同版本／对象仍分别核对 |
| R19 语义上下文 | 证据预览、证据索引只取当前可用解析 | Qwen／人工原判定流程未改 |
| NDT 表、R39 引用字段、R40 记录／要求 | 不再把同版重跑当两份表或文件；R40 来源检查核对最新状态 | 真正多文件、未读页与对象歧义继续阻挡 |
| 管线及设计事实 | 冻结任务排除旧解析；失败的当前解析仍列为已上传但不可解析 | 无冻结快照的历史管线兼容路径仍沿用原读取方式 |
| 条件试跑、工具 OCR／字段／表／印章读取 | 候选及运行时工具只见当前可用尝试 | `runtime_tools.selected_parse_results` 再导出接口保留供旧调用方使用 |
| 来源覆盖及 grounding | 覆盖检查区分当前失败与缺页；正式任务的 OCR grounding 即使未选页码也只用当前解析 | 独立的 `extracted_fields`、`evidence_links` 仍按原冻结版本／页码契约读取，未冒称与 OCR 尝试同源 |
| Jev 全文和支持页 | 使用同一当前尝试与可用性口径 | 仍为影子运行，不改正式裁决 |

页码裁切原本会丢失 OCR 的完成时间，导致先裁切再选最新时按记录 ID 错选。
现只保留排序所需的时间和状态元数据，不让页外正文、摘要或表格回流。

回归使用同版旧／新不同内容、最新失败、无可靠顺序、页码裁切、人工字段修正，
并沿真实 R40 工具判定及逐管线事实验证。原有 R39／R40 测试中，无时间戳的
重复解析继续判证据不足；R39 待人工复核的已定位内容仍保留缺页告警和已知失败。
这些是合成回归，不等于七项目 Jev 准确率或生产部署验收。

验证：在 `backend/` 工作目录运行完整测试 **5,438 通过、81 跳过、0 失败**，
全仓 Ruff 棘轮 **286／286**，改动文件 Ruff 与 `git diff --check` 通过。
81 条环境选择性跳过不代表 PostgreSQL、MinIO、Temporal 在本批重新实测。
