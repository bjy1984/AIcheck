一句话：把「焊接节点重点优化」推到了全部节点，顺带清掉了界面上四类原始代号，

## 一、焊接（用户指定的重点）

### 平台核证进事实链，并挡住张冠李戴

节点 24 实测链条：

| 阶段 | all_codes_decoded | 说明 |
|---|---|---|
| 起点 | 0/4 | OCR 把代号认坏（CTAF/SHAW/PTAV），解码器全拒；平台核到的原文只进 certificate_facts，r24 的焊工事实是另一个 builder 建的，拿不到 |
| 接上平台 | 4/5 | **其中四个是别人的**——平台按李卫伍的证件号返回的持证人是「赵相军」 |
| 加姓名核对 | 0/4 | 姓名不符判 verified_mismatch，不覆盖不标已核验 |
| 平台恢复后 | 2/5 | 姜军 verified_match（登记原文）；李卫伍 mismatch（保留 OCR） |

`verified_mismatch` 是这轮最有价值的产出：证件号是 OCR 读的，错一位就查到别人，
照抄回来等于把另一个人的合格项目安到这名焊工头上，比查不到危险得多。
`check_certificate_validity` 原来只看有效期与范围，人证不符照样判「核验通过」——
现在它把该证判成证据不足，界面上不再出现「与平台登记不一致」配「核验通过」的自相矛盾。

### 事实去噪（对全部节点生效）

- 一个焊工一条证（OCR 把两人拆成 15 行，10 行是空模板）。
- **一个业务字段都没有的表格行不成事实**——病根是通用的：节点 26 的 56 条里 55 条重复、
  节点 29 的 53 条全是空壳、节点 32 的 19 条同理。
- 同一张证被 r24 builder 和证书链各产一条 → 按 certificateNo 去重（**不能按 value**：
  节点 1 的「图签设计单位/设计章单位」值本来就该相同）。
- 引文从 `json.dumps(row)` 改成「键：值」，并滤掉 OCR 读坏的列名；证据带 documentId，
  点文件名直接打开原件。

## 三、节点页信息密度

节点包返回 258KB，页面原来只渲染 2.2KB——「审查所需资料」表锁在 submission 审计项下，
而节点页目录只保留 ai_review / human_review 两项，那张表永远打不开。现在：

- 七个审计项的状态条（含 OCR/证据项的问题摘要，可点进去）
- 本节点所需资料卡：必传 x/y、缺什么、谁该传、去挂接（计数全部从同一份行数据算，不会自相矛盾）
- 每个原子项的原因 + ✓/✗ 逐条检查（实际 vs 要求）
- 事实与证据按类型归组折叠；认不出可核字段的表格行汇总成一句并指到原件
- 引用的标准条款：`TSG Z6002—2010 · 第三章 · p12-c13 · 第 12 页` + 原文 +
  **红标「已被 TSG Z6002-2026 取代（2026-08-01 施行）」**
- 颜色口径（用户定）：通过=绿、证据不足=黄、错误=红；「需人工判断」用蓝（等人拍板 ≠ 缺东西）

**不用改 prompt**：模型早就在引条款（kbRefs.clauseIds 从检索包选 id，不自己背原文——
背原文正是幻觉入口），缺的只是把 id 解析成标准名/章节/原文。

## 四、三个真缺陷

1. **节点复核一直没用结构化发现**：后端落在 `review_run.findingDrafts`，前端读 `run.findings`，
   永远是空 → 一路退回「解析自由文本」，证据引用、规则依据、降级原因、标准条款全丢。
2. **一次失败的复核把上一次好结果挤掉**：基础设施抖动后节点只剩一句「执行失败」。
   现在回退显示上一次成功的结果 + 失败横幅。
3. **入队失败留下假「处理中」**：`review_run_execute.delay()` 抛异常时运行已经以 queued
   落库，没人管它。现在当场落 `failed_to_start` + `review_run.dispatch_failed` 事件。

## 五、我造成的事故

一次发起 30 个节点复核 + 反复部署 → Docker build cache 堆到 44GB → 99G 盘满 →
Postgres 进入恢复 → API 短暂 not_ready（蓝绿守卫没切流量，旧容器一直在服务）。
清理后恢复。此后：批量复核每批 4 个、部署后 `docker builder prune -f`、`df` <10G 停手。

另有两次把自己的测量错误当成产品 bug（改 hash 不触发重载、视窗放大后坐标系错位），
用 DOM 直接 click 验证后一切正常。**先证伪自己的测量，再下产品结论。**
