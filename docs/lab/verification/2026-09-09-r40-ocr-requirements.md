# R40 明示要求文件版本到原文比較

R40 事件 member 可提供 requirementsVersionId，只有該版本已選取、解析唯一、租戶一致，且原文明示工藝規程／操作指導書、檢測方法與事件相同，才補入要求。已有 requirements 業務表時不覆蓋；不自行找一份規程當要求。

ndt_procedure_v1 增加「檢測比例要求」「技術等級要求」明示字段。比例僅接受明示至少／不少於／不低於／≥／>=、不超過／最多／≤／<=、等於／= 加百分比；等級僅明示等於／=。裸值沒有運算符時保留未知，不預設最低比例或等級高低。原文身份與數值字段進入同一證據門檻與固定頁碼範圍。

79 項相關測試通過，涵蓋原文要求後處理至實測值比較、上下限與相等、裸值／模糊指示、未指定／未選版本、方法不符、重複／低置信度、頁碼排除與等級；既有 R40 原文、缺頁和規程 OCR 回歸通過。Ruff 289／289、monolith 通過。輸出：r40-ocr-requirements.txt。

界限：requirementsVersionId 來自合成標準化事件清單，本輪未新增人工確認映射 UI，也不證明 OCR 能從真實清單解析系統版本 ID。這是來源適配契約與比較鏈路驗收；實際清單／版本映射、規程批准有效性、要求完整性、標準適用性、報告結論及成套真實案件仍待驗。三項 pendingCapabilities 和發布阻擋保持，整體未證明達 90%。
