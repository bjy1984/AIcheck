# R11：批復與所提供採用記錄的時間比較

## 實作

既有 R11 簽批 profile 增加 planUsage，來源為 construction_plan_usage 明確表。仍用相同 projectId／planVersionId／ownerOrganizationId／approvalCycleId 對應；多筆採用記錄不任取第一筆。批復與採用各自的 documentVersionId 必須與自己的引用一致，時間字串須在該來源 quotedText 中完整出現，不用報告日期、上傳時間或模型推測補值。

新 `r11_approval_timing.py` 比較 approvedAt 與 startedAt；僅在批復為 approved、採用記錄為 started 且來源匹配時執行。尚未開始或缺採用記錄是證據不足，不推定不適用。

- ISO 日期以整天區間處理，同一天不能推斷先後。
- 帶時區的 ISO 時間按其記錄精度形成區間（秒或小數秒）；不同時區可比較。區間重疊時保持不足，不把秒精度偷偷補成毫秒精度。
- 日期與時間戳不混合推斷；無時區、只到月份、無效日期等保持不足。
- 批復區間完整早於採用區間則局部 passed；完整晚於採用區間則 failed；同時保留其他缺簽／缺資料事項。

專用工具版本升 r11-documented-plan-approval-v2。原子綁定的兩項 pendingCapabilities 保留，因此局部時間比較通過不使 R11-01 完整通過；歷史快照與原 36 試點不變（R11 非試點）。

## 驗證

151 項相關測試通過：時間精度、同日／同時區間、跨時區、無時區、無效日期、來源字串／版本／批次、晚批復與缺簽共存，以及固定來源表→實際 R11 節點計畫→專用工具的先於／晚於／同日結果。每側引用仍指向各自的固定版本，來源狀態不修改。

Ruff 289／289、monolith、diff check 通過。日誌 `2026-09-09-r11-approval-timing-tests.txt`。此為合成明確来源表驗收，非真實簽章／採用記錄的 OCR 和登入案件驗收；本輪未再次完整後端重跑。

## 尚未完成

比較對象只是目前提供的單筆採用記錄，未證明它是首次採用，也未覆蓋全部使用事件。批復撤銷／條件／有效性、簽名真偽與權限、多方案／多事件清單及原文 OCR 適配仍待完成。不能把此時間比較寫成「批復有效性與全部時序已驗收」，owner_reply_validity_and_timing 仍阻擋發布。R11-03 施工標準及其他規則／標準資料也仍在完整計畫中，整體未證明達 90%。
