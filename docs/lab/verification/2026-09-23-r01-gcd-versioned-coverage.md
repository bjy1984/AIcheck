# R01 设计许可 GCD→GC2 版本化修复（2026-09-23）

[市场监管总局 2021 年第 41 号公告附件 1 注一](https://www.samr.gov.cn/tzsbj/dtzb/gzdt/art/2021/art_ab36c6d55fde4d7daf8264578997607e.html)
明确压力管道设计、安装许可参数中 GC1、GCD 级覆盖 GC2 级。原 R01 业务方法只写
GC2 或 GC1 许可，工具也按这一已冻结文字执行。本批在 Lab 分支建立新版，而没有
改写旧版任务或把 GCD 反向当作 GC1 许可。

- 业务包版本 `2026.09.23`，R01 版本 `engineering-inspection-r01-v20260923`；
  R02–R69 的规则版本不变。原始方法仍保存在 `sourceWitness`，新增的执行方法、
  原子项 AC-R01-02／04 和模型提示共同写明 GC2 可由 GC2、GC1 或 GCD 覆盖。
- AC-R01-02／03／04 冻结 `scopeProfile=design-license-scope-cn-v2`。两个确定性工具
  读该参数；旧任务无参数或使用 `v1` 时维持 GC1／GC2 口径，新任务使用 `v2`
  才加入 GCD。未知版本返回证据不足。设计证以外的证照不借用这项覆盖规则。
- 对话 Agent 单独调用设计许可范围工具时，也由当前 ReviewRun 或工程的冻结绑定
  注入相同参数；模型不能换成另一版本。找不到旧工程的冻结规则时拒绝调用，
  避免拿当前新版代替旧版。
- 新业务包按不同 release ID 发布到条款库时，旧 release 可以并存；既有项目和
  ReviewRun 的规则、工具及条款快照不自动重写。部署前仍需对真实旧项目核对版本
  绑定和快照，部署后不能用健康探针替代原项目重放。
- 全量生成器目前会重拆其他规则，将原子项从 194 变成 213，属既有生成漂移。
  本批未接纳那批无关变更；使用
  `python -m scripts.regenerate_business_rules --only-rule R01 --check` 核验 R01 来源，
  并以测试逐项比对 R01 五条原子项及工具绑定。再次全量生成前须先处理该漂移。

本地验收涵盖旧版 GCD→GC2 不通过、新版通过、GC2 不反向覆盖 GCD、GCD 不覆盖
GC1、缺资料和未知版本均不放行，以及两个版本的条款 release 并存。范围工具与
证照工具在新版同判通过，对话 Agent 的新旧版本路由及拒绝覆盖也有测试。完整后端
`--collect-only` 收集 5,488 项（之后又加入两条对话测试）；最终全套
**5,409 通过、81 跳过、0 失败**。首次运行的一条旧 PostgreSQL 锁替身接口错误、
第二次运行的巨型路由文件行数棘轮失败都已修复，最终结果取第三次运行。
两个条款资产审计均通过：69 条规则、194 原子项和 194 工具绑定保持一致。
