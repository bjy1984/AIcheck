   `/home/dev-bjy/aicheck-secrets.env`。正式 Jev 开关仍保持关闭。

   工作树中找到；`scratchpad/shadow/` 也不存在。只有研究报告，不能重造题目或宣称
   0.68／0.72 已经校准。标注后才能设置校准、拒绝和 UI 开关。
3. **上游两个生产缺陷**。设计证 GC1 对 GC2 的双工具矛盾已在本分支按同一
   冻结业务规则修正；Jev state 的矛盾排除守卫仍保留。节点 3 的已知「单位名称被抽成
   评价句」已加窄范围守卫。两处都尚未重放原生产 OCR，不能记为实机修复完成。
4. **实机验收**。需要原始七项目影子产物或获准后的受控回放，核对 R25/29/32 的
   71 条假事实、219 格方向对照、逐句抓错率、R19 八项语义题及大文件分拆。
   单份超过 40,000 字的文件目前会跳过 Jev；不能宣称两格超长已补跑。
5. **费用优化与正式队列**。当前 Qwen 仍对所有进入原流程的节点生成发现；“只给人工
   队列生成解释”的省费改造尚未实施。R19 仍按现有语义路径裁决，Jev 暂不替换它。
6. **清单模式**。`AICHECK_REVIEW_PROMPT_MODE=checklist` 的清单结论受独立的条件一致性
   契约保护；本分支的逐句核对只针对自由发现模式。清单模式会明确记录
   `unsupported_checklist_mode`，不会擅自改写固定条件判定。

## GC2 许可覆盖的双工具一致性

- [市场监管总局 2021 年《特种设备生产单位许可目录》注一](https://www.samr.gov.cn/tzsbj/dtzb/gzdt/art/2021/art_ab36c6d55fde4d7daf8264578997607e.html)
  明确 GC1 级覆盖 GC2 级，适用于压力管道设计、安装许可。原 `AC-R01-02`
  的范围工具据此判通过，但 `AC-R01-03` 所用证照工具只按代号完全相等比对，
  把同一 GC1 证错误判为不覆盖 GC2。
- 设计许可证的两项工具现在共用同一 GC1→GC2 规则；证照工具版本升为
  `certificate-validity-cn-v2`，留痕增加每项要求可接受的许可级别。真实工具输出
  注入 Jev state 前不再构成该例的矛盾；原有「遇到矛盾两侧都不注入」守卫未撤除。
- 本批相关 **206 项测试通过**，涵盖 GC1 覆盖 GC2、真正缺级别、非设计证不借用该
  覆盖关系和 Jev state 一致性。旧的线上留痕仍记录历史误判，不自动改写或重跑。
- 该官方目录同时写明 **GCD 级也覆盖 GC2 级**。现已在本分支建立
  `engineering-inspection-r01-v20260923` 和业务包 `2026.09.23`：原始见证文字存入
  `sourceWitness`，新版执行方法与 AC-R01-02／04 明确加入 GCD。冻结绑定参数
  `design-license-scope-cn-v2` 传给范围及证照工具；旧版缺省 `v1` 保持原行为。
  这仍未部署、未重跑历史任务。原生产案例重放及旧项目实库兼容性仍待执行。详情见
  [`2026-09-23-r01-gcd-versioned-coverage.md`](../verification/2026-09-23-r01-gcd-versioned-coverage.md)。
- 新版对话 Agent 的直接范围工具也从任务或工程快照读冻结参数，拒绝模型覆盖版本；
  找不到旧版本快照时拒绝调用，不使用当前包猜测。最终后端全套 **5,409 通过、81
  跳过、0 失败**；条款资产与节点编号审计通过。全仓 Ruff 棘轮仍为 318 / 289，
