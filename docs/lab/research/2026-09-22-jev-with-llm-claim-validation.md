# 配合架构实测：大模型出主张，Jev 验证

前两轮影子运行测的是 Jev **单独**回答 194 个固定原子项题，大模型不在回路里。
这一轮补测方案真正要的那条路：**真实的大模型发现 → 拆成主张 → Jev 逐条验证**。

## 一、为什么这轮能算出准确率

主张里的**编号和数值**（`pWPS-2023-01`、`110-120A`、`GB50235`）是否字面出现在该节点资料全文里，
可以机械判定。措辞不同但意思对的情况会被误判为「不在」，所以这不是全部真相——
但反过来那一侧是硬的：**一个具体编号在全文里根本找不到，却被写成「查到」，那就是编造。**

从 ECD202 的生产 `review_runs` 里抽出真实发现，正则提取这类可机械判定的串，
拿该节点的真实 state 问 Jev「资料原文里是否出现这个编号/数值」。

## 二、结果

| | |
|---|---|
| 主张 | **63 条** |
| 机械真值 | 资料里确实有 47，**根本没有 16** |
| Jev 判断与机械真值一致 | **63 / 63 = 100%** |
| 其中 conf ≥ 0.90 | 61 条，全对 |
| 「资料里没有」的 16 条 | Jev 全部答 absent，**16/16，信心 1.00** |

一条 unsure 都没有，一条误判都没有。

## 三、抓到了什么

节点 25 的真实发现，标题《WPS 參數與 PQR 一致性無法核驗》，描述写着：

> 查到 pWPS-2023-01 記載焊接方法 GTAW+SMAW、電流範圍 **GTAW 110-120A/SMAW 120-130A**、
> 電壓 **GTAW 10-15V/SMAW 25-30V**、焊接速度 5-7cm/min

这四组电流电压数值，**在 `9.1金辉焊接工艺评定20.pdf` 全文里一个都不存在**。
（与之印证：单独问 Jev「本资料是否记载了 WPS 的电流、电压、焊接速度、层间温度」，
它答「没有记载」conf 0.91；确定性层对该节点三个原子项也全判证据不足。）

同类还有节点 59、50 引用的 `GB50235`、`GB50236`，节点 12 的 `TS2713506`、`AF980885`。

## 四、现在的校验层漏掉了它们

含编造串的发现共 **11 条**，其中生产的 `unsupportedClaims` **完全为空的有 8 条**——
系统一点没察觉。而且这些发现的 `groundingStatus` 标的是 **`grounded`**（通过了证据落地校验）。

原因在前一份基线报告里已经查清：现在的校验是**子串匹配**，看「发现里的词有没有在证据里出现」。
描述里的中文词（焊接方法、电流范围、电压）在资料里都有，于是整条通过；
而**被编造的是数字**，子串匹配对数字没有任何约束力。

它们真正被标出来的是另一回事：`EVIDENCE_REF_LINK_NOT_FOUND` / `EVIDENCE_REFS_MISSING`，
说的是「引用链接找不到」，不是「你说的数值是编的」。

## 五、这回答了哪个数

| 目标数 | 状态 |
|---|---|
| 复现率 | 已答：三态 97.5%，自动路径 100% |
| **主张确认率 / 抓错率** | **本轮已答**：63 条机械可判主张 100% 判对；16 条编造串 100% 抓出，其中 8 条现有校验完全没察觉 |
| 0.70 阈值下的准确率（原子项级） | 仍未答，要人工标 33 题 |

## 六、诚实的边界

- **样本小**：63 条主张、16 条编造、11 条发现，只来自 ECD202。方向明确，量级不可外推。
- **只测了可机械判定的主张**。措辞类主张（「审批手续齐全」）没法这样验，
  那部分要靠人标，本轮没测。
- **这轮的题是我用正则出的，不是大模型出的。** 真实架构里由大模型把描述拆成主张，
  拆得好不好会影响结果。**「大模型框歪了题、Jev 在错框里自信作答」这个风险仍未测过。**
- 机械真值把「意思对但措辞不同」判为 absent；本轮 16 条 absent 我逐条看过，
  都是实打实的编造数值，没有这类误伤。

## 七、结论

配合架构的核心价值在这一轮被具体测到了：**大模型负责读和写，Jev 负责逐句核对，
而它核对的正是现在的校验层结构上看不见的那一类错——编造的数字。**
