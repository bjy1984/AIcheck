# 用 System One 模型（Jev）按审计清单直接出结论：与现行方案对比

问题：审计清单是固定的（69 个节点、194 个原子项），能不能把每个原子项做成一道选择题，
把节点挂接的资料当上下文，让 Jev 直接选「通过／未通过」？

结论先行：**能做，但不该做成裁决层；做成辅助层收益很大。** 下面是依据。

## 一、现行方案到底是什么

先把误解澄清：现在的结论**不是大模型判的**。

| | 数量 | 说明 |
|---|---|---|
| 节点 | 69 | `engineering-inspection-r01` ～ `r69` |
| 原子项 | 194 | `atomic_checks.yaml` |
| 其中 `evidence_and_deterministic_rule` | **186** | 结论由确定性工具算出：期望值 vs 实际值 |
| 其中 `evidence_and_llm_semantic_judgment` | **8** | 全在 R19（境外牌号材料），需要语义判断 |

一次节点复核的流水线（`execution.py` 的图节点）：

```
load_context → load_ocr_result → run_rule_engine → retrieve_knowledge → build_prompt
→ llm_generate_findings → critic_review → evidence_validation → reference_validation
→ schema_validation → quality_gate → persist_drafts
```

- **结论**：`run_rule_engine` 跑绑定的工具（`decode_welder_qualification`、`check_certificate_validity`、
  `verify_welder_on_platform`……），每项产出 `checks[]`，每条有 expected / actual / passed。
  三态：通过、证据不足、需人工判断。
- **大模型**：只负责写「发现」——解释、建议动作、从检索包里选条款 id。它不决定通过与否。
- **耗时**：单节点数分钟，大头在 OCR 和检索，不在判定。
- **费用**：主要是 `llm_generate_findings` 那一次调用。

## 二、Jev 方案怎么映射

Jev 的 API 形状和这个想法是一比一的：一个 `state` 挂多个 `questions`，共用上下文，平行评估。

```json
{
  "state": "<节点 24 挂接资料的 OCR 全文>",
  "questions": {
    "AC-R24-01": {
      "type": "choice",
      "instructions": "核验焊工资格证原件或经核验复印件、人员身份及作业日期有效性……",
      "criteria": {
        "passed": "资料明确满足要求",
        "evidence_insufficient": "资料缺失、读不清或不足以判断",
        "human_review_required": "资料有但需要人判断"
      }
    },
    "AC-R24-01-page": {
      "type": "choice",
      "instructions": "哪一页支持上面的结论",
      "criteria": { "p1": "…", "p2": "…" }
    }
  }
}
```

回：每个选项的概率、一个 confidence、70～500 ms。

## 三、逐维对比

### 1. 结论从哪来，能不能追溯

| | 现行 | Jev |
|---|---|---|
| 结论依据 | 每条 check 的期望值 vs 实际值，人能复算 | 一个概率分布 |
| 证据定位 | 引文、页码、bbox、标准条款原文 | 可以再问一题「哪页支持」，但没有引文和原因 |
| 可复现 | 同输入同输出 | 模型版本升级（jev-1.13.0 → ?）结论可能变 |

监检结论要能被复核、被追问。「未通过，0.87」在监检语境下**不是一个结论，是一个提示**。
这是最根本的差异，和模型好坏无关。

### 2. 精确判断 vs 语义判断

现行 186 项是精确判断，例如：

- 作业日期是否落在证书有效期内——日期比较
- `SMAW-FeⅡ-6G` 覆盖不覆盖 `2G`——按 TSG Z6002 的位置覆盖表解码
- 持证人是否就是证件号登记的人——**去公示平台查**

这三类 Jev 一类都做不了：它不算日期、不查表、不上网。本轮最有价值的产出
`verified_mismatch`（李卫伍的证件号在平台登记的是赵相军）来自平台交叉核验，
分类器看着资料永远发现不了。

反过来，8 项 R19「境外材料标准与使用经历」「化学成分与性能等同性」是语义题，
现在靠大模型自由文本，Jev 把它结构化正合适。

### 3. 资料缺失时的行为

现行：没挂文件 → `checkCount = 0`，界面写「没有可核资料」，不出结论。583 项是这个状态。
Jev：**永远会选一个**。资料为空时它照样给 `evidence_insufficient: 0.9` 或者更糟的
`passed: 0.6`。必须在前面加一道门：没资料不问。这不难，但要记得。

### 4. OCR 质量

同一份输入。现行的确定性层有一堆专门认坏数据的逻辑（占位符、自动编号列、空模板行），
认出来就降级到证据不足。Jev 对坏 OCR 的校准没有数据——它可能对一堆乱码给出高置信度。
这是试点必须测的一项。

### 5. 速度与费用

Jev 明显赢：毫秒级、输入 $0.042/MTok、输出免费。
但要看清赢在哪：流水线的时间大头是 OCR 和检索，判定层本来就不慢；
费用大头是 `llm_generate_findings`。Jev 能省的是那一步——
**如果只对「未通过／需人工」的项目再叫大模型写解释，费用能降一大截**。这是真收益。

### 6. 校准与反馈闭环——Jev 带来的新能力

现行系统没有「不确定度」这个概念：通过就是通过。
Jev 的概率分布可以用来**给人工复核排队**：confidence 低的先看，高的后看。
真实人工结论现在约等于零（证据链确认 420 条 0 驳回），有了排队信号，
人工的注意力才能花在刀刃上。这是现行方案完全没有的东西。

前提：概率得校准过。没有标注集之前，0.87 只是个数字。

### 7. 规则换版

现行把 `transitionEffectiveDate: 2026-08-01` 写在工具绑定里，换版是代码可见的。
Jev 只认 `instructions` 里的文字，每次都要把「8 月 1 日前按 2010 版」写进去，
漏写就静默用错版本。

### 8. 幻觉

现行大模型写发现会幻觉，靠 critic_review 和 evidence_validation 拦。
Jev 结构上不会输出没定义的值，但**会自信地选错**——这两种错的形态不同，后者更难发现，
因为它看起来很像对的。

### 9. 合规与连通性

Jev 服务器在美国西岸。生产机房连 GitHub 都不通，大模型走百炼国内端点。
压力管道监检资料出不出境，是政策决定，不是技术决定。这一条不解决，后面全是白做。

### 10. 工程量

接一次 HTTP 调用很小。**但把它做成裁决层就不小**：要重写 output_contract、
人工确认流程、界面上这周刚做好的 expected/actual 逐条核查全部作废，
因为 Jev 不产出这些。

## 四、汇总

| 维度 | 现行 | Jev 当裁决层 | Jev 当辅助层 |
|---|---|---|---|
| 可追溯、可复算 | 强 | 弱 | 不受影响 |
| 精确判断（日期/解码/平台核验） | 强 | 做不了 | 不受影响 |
| 语义判断（R19 等 8 项） | 自由文本 | 结构化，合适 | 结构化，合适 |
| 资料缺失 | 明确说没有 | 会硬答，需加门 | 需加门 |
| 坏 OCR | 有识别逻辑 | 未知 | 未知 |
| 速度/费用 | 判定不慢，解释贵 | 判定极快，解释没有 | 解释只对问题项生成，费用降 |
| 不确定度/人工排队 | 没有 | 有 | **有，新能力** |
| 规则换版 | 代码可见 | 靠提示词 | 靠提示词 |
| 可复现 | 是 | 随模型版本变 | 不影响裁决 |
| 合规 | 国内 | 出境 | 出境 |
| 改造量 | — | 大，且丢掉本周成果 | 小 |

## 五、建议的架构：Jev 放在确定性层旁边，不放在它上面

1. **8 项 R19 语义题**：直接用 Jev 出三态结论，替代自由文本。
2. **人工复核排队**：对全部原子项跑一遍 Jev 作为「第二意见」。
   它和确定性层**不一致**、或 confidence 低的，排到人工队列前面。不一致本身就是信号。
3. **解释按需生成**：只对「未通过／需人工」再叫大模型写发现，通过的不写。
4. **表格行角色分类**：表头／小标题／数据行／空模板，替代现在的正则。
   单栏小标题那一行至今治不了，就是这一类。
5. **资料要求命中**：档名与「本节点所需资料」的匹配，替代关键词。

不动的：186 项确定性工具、平台核验、条款解析、expected/actual 逐条核查。

## 六、试点

- 范围：ECD202 节点 24、25，8 个原子项，每项两题（三态结论、支持页）。
- 对照：确定性层结论 + 本轮人工逐条读过的结果，约 50 条标注。
- 看：三态准确率；confidence 与对错的相关性；坏 OCR 上的表现；中文；单个 state 装不装得下节点全文。
- 费用可忽略，一天。

**前置两件事要项目负责人定**：资料能否送境外服务；API key。
两件不定，试点不能开。
