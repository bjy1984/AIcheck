# Jev 接入方案 v2（按实测结果修订）

前一版（`2026-09-22-jev-vs-current-verdict-layer.md`）是纸面推演，
实测（`2026-09-22-jev-boundary-test.md`）推翻了其中三条，坐实了两条。这一版按实测重排。

## 一、实测改变了什么

| 前一版假设 | 实测 | 对方案的影响 |
|---|---|---|
| 没资料会硬答，要加门 | 答证据不足 conf 1.00 | **不用加门** |
| 不会算日期、不懂位置覆盖 | 月级边界 0.99、6G/2G 双向对 | 语义题范围可以放宽到「规则明确写在指令里」的项 |
| 上下文装不下整个节点 | 上限 53k 字，最大节点 20k 字 | **一个节点一次调用**，不分片 |
| 坏 OCR 上校准未知 | 表格分类 1.00、表头识别 0.97 | 表格行角色分类可以直接上 |
| 生产机房可能打不通 | 容器内 0.56s 可达 | 无网络障碍 |
| 它自己能发现人证不符 | 不能（0.36 答错）；给了平台数据 0.96 判对 | **取数留给流水线，判断交给它** |
| 延迟 70–500ms | 实测 1.1–2.1s | 只能异步/批量，不能放在交互路径上 |
| 不产出引文页码条款 | 确认 | **仍不能单独当裁决层** |

一句话：**边界不在「它会不会判」，在「它拿没拿到数据」。**
把确定性层算出来的东西喂给它，它的判断质量和置信度都上去了。

## 二、修订后的架构：一条并行的「第二意见」通道

```
load_ocr_result ──► [新] 表格行角色分类 ──► 事实构建 ──► run_rule_engine（确定性，不动）
                                                              │
                                                              ▼
                                            [新] 组装 state：资料全文 + 确定性层已核实事实
                                                              │
                                                              ▼
                                            [新] Jev：每个原子项一题（三态）+ 一题「支持页」
                                                              │
                        ┌─────────────────────────────────────┴───────────────┐
                        ▼                                                     ▼
              与确定性层一致 且 conf ≥ 0.70                          不一致 或 conf < 0.70
              → 结论照旧，标「第二意见一致」                          → 人工队列前排，标「分歧」
                                                                             │
                                                                             ▼
                                                        llm_generate_findings 只对这些写解释
```

三条原则：

1. **裁决权不变。** 结论仍由 186 项确定性工具产出，带 expected/actual/引文/条款。Jev 只加一列。
2. **取数在前，判断在后。** state 里必须包含平台返回、解码结果、日期计算这些**流水线已经算出来的事实**，
   不然它会像 T6 那样在缺数据的题上低置信度乱选。
3. **不确定就转人。** 0.70 阈值来自 12 条校准（≥0.70 全对），上线前要用更大标注集重定。

## 三、state 的组装规范

顺序固定，每段带标题，避免 T8 里「上下文被砍碎就判错」的情况——**永远给整节点全文，不给片段**：

```
【节点】24 焊工资格证及持证合格项目
【规则】RULE-ENG-INSP-R24；业务日期 2026-09-22；TSG Z6002 换版日 2026-08-01
【作业事实】作业日期 2026-03-12；母材 20#；管径 Φ219×7；位置 6G；方法 SMAW

【文件 1/3：10.姜军焊工证.pdf】
[第1页] …layoutBlocks 按阅读顺序…
[第1页 表格] <table>…</table>
[抽取字段] 姓名：姜军 …

【文件 2/3：焊工清单.docx】…

【流水线已核实事实】
- 公示平台：证件号 511621198504208836 登记持证人 姜军，与资料一致（verified_match）
- 公示平台：证件号 410521198609180550 登记持证人 赵相军，与资料「李卫伍」不一致（verified_mismatch）
- 代号解码：SMAW-FeⅡ-6G 解码成功；CTAF-… 无法解码（OCR 疑误）
- 有效期：姜军 2025-10 ～ 2029-09，作业日在期内
```

多人文件（焊工清单）在「按人问」的题上要**按人拆题**，T6 的错就是多人混在一份里。

题目模板（每个原子项两题）：

```json
"AC-R24-01": {"type":"choice","instructions":"<atomic_checks.yaml 原文 instruction>",
  "criteria":{"passed":"资料明确满足该项要求","evidence_insufficient":"资料缺失、读不清，或不足以判断","human_review_required":"资料存在但需要人来判断"}},
"AC-R24-01.page": {"type":"choice","instructions":"哪一份文件的哪一页最直接支持上面的结论",
  "criteria":{"f1p1":"10.姜军焊工证.pdf 第1页","f2p1":"焊工清单.docx 第1页", "...":"...","none":"没有任何页支持"}}
```

固定用 `"model":"jev-1.13.0"` 而不是 `jev-latest`，结论要可复现；每条结果落库时记模型版本。

## 四、分期

### 第 0 期：前置（不写生产代码）

- [ ] **合规结论**：资料出境是否允许。不允许则整个方案止步于此，或改问供应商有无国内/私有部署。
- [ ] 轮换这把 key；新 key 只进 `/home/dev-bjy/aicheck-secrets.env`，走现有 `AICHECK_*` 密钥机制。
- [ ] 标注集：从 7 个项目的 sweep 结果里抽 **200 条原子项**，由监检人员标三态。
  这是校准阈值和验收的依据，12 条不够。

### 第 1 期：影子运行（只读，不进界面）

- 一个脚本（同 `sweep_deterministic_layer.py` 的路子，容器内跑）：对 7 个项目全部节点组装 state、
  跑 Jev、把结果写到 lab 集合 `jev_shadow_runs`（不碰 review_runs）。
- 产出：与确定性层的**一致率矩阵**（节点×项目）、**校准曲线**（用第 0 期标注集）、分歧清单。
- 验收：conf ≥ 阈值的部分准确率 ≥ 95%；分歧清单里人工认定 Jev 对的比例 —— 这个数决定它值不值得进界面。
- 费用：7 项目 × 69 节点 ≈ $0.1。

### 第 2 期：表格行角色分类（第一个进生产的点）

- 位置：`r13_facts.py` 的 `_row_quote` / `_has_business_content` 之前，给每张表的每一行问一题
  `{header, data, section_title, empty_template}`，再问一题「这张表是什么」`{力学性能试验, WPS参数, 焊工证, 材质单, …}`。
- 替代：`_columns_are_auto_numbered`、`is_placeholder` 里针对表头的启发式；治好单栏小标题那一行；
  修正「力学性能表被归成 wpsItems」的分类错。
- 守卫：环境变量开关；Jev 不可达或 conf < 0.90 时回退到现有正则；沙箱测试用录制的响应，不打外网。
- 验收：七项目确定性扫描前后对比，`insufficientReasons` 与事实条数的变化；节点 25/29/32 的 19 行假 WPS 事实应消失。

### 第 3 期：第二意见进界面

- `review_run` 增加 `secondOpinion: {choice, confidence, model, agreesWithRuleEngine}`。
- 界面：逐项核查每行多一个小标（「第二意见一致」/「分歧，建议人工」），人工队列按 分歧 > 低置信 > 其余 排序。
- `llm_generate_findings` 改为只对 分歧/低置信/未通过 的项目生成解释；通过且一致的不生成。**这是费用降下来的那一刀。**
- 验收：人工复核队列的首屏命中率（人工改判的项目是否集中在前排）。

### 第 4 期：R19 的 8 项语义题

- 直接用 Jev 三态替代自由文本判定；解释按需生成。范围小，单独一期是为了不和第 3 期混在一起看效果。

## 五、明确不做的

- 不用 Jev 替代 186 项确定性工具。
- 不把 Jev 放在同步请求路径上（1–2 秒）。
- 不用 `jev-latest`。
- 不给片段，只给整节点。
- 不在没有标注集的情况下定阈值。
