# 大模型发现层的实测基线，与「大模型出题、Jev 作答」能改变什么

前面的评估都建立在一个假设上：大模型那一层有多少错。这份把它量出来。
数据：P-2026-ECD202 全部 review_runs（223 次运行、32 个节点、1 038 条发现），生产留痕原样导出。

## 一、基线：大模型的发现，走到人面前的路上发生了什么

| 指标 | 数值 | 占比 |
|---|---|---|
| 发现总数 | 1 038 | |
| 被校验层判 `insufficient_evidence` | **699** | **67%** |
| 判 `grounded` | 339 | 33% |
| 带「不支持的主张」的发现 | 690 | 66% |
| 不支持的主张总数 | 1 417 | 平均每条发现 1.4 条 |
| `evidenceRefs` 为空 | 578 | 56% |
| `clauseRefs` 为空 | 765 | 74% |
| 被标 `UNSUPPORTED_LLM_CLAIM` 降级 | 451 | 43% |
| 系统算出的 confidence < 0.7 | 954 | **92%** |

三分之二的发现，系统自己都不敢用。注意 `confidence` 不是模型的自我估计，是系统按
`grounding_coverage` 算的引用覆盖率——它衡量「引了多少」，不衡量「对不对」。

按节点看，grounded 比例从 0%（节点 46）到 68%（节点 32）不等，不是个别节点的问题。

## 二、现在的「主张校验」在校验什么

把 1 417 条「不支持的主张」摊开：

| 形状 | 条数 |
|---|---|
| ≤ 6 个字的碎片（`许可证`、`有效期`、`焊接方法`、`规格`） | **640** |
| 系统代码而非主张（`EVIDENCE_REFS_MISSING`、`claim_to_evidence_mismatch`、`positive_business_conclusion`） | 252+ |
| 含日期字符串 | 65 |

最常见的一条「不支持的主张」是 `许可证`，出现 101 次。理由一律是
`not_present_in_supplied_evidence`——**字面上没在证据里出现**。

也就是说，现在的校验是**子串匹配**：发现里写了「许可证」而证据文本里没有这三个字，就判不支持。
它不知道主张是真是假，只知道词出没出现。两个后果：

- 大量误伤：「WPS/PQR」这个词不在 OCR 文本里，不等于「缺 WPS/PQR」这个判断错了。
- 真错放过：只要用词和证据重合，编出来的结论照样通过。

这一层现在**不产生「这条结论对不对」的信号**，只产生「这条结论用词和证据像不像」的信号。

## 三、可复现性：同一份输入跑两次

取相邻两次运行、`inputHash` 相同、prompt 版本相同、模型别名相同的 145 对（严格同条件）：

| 指标 | 数值 |
|---|---|
| 发现内容软一致率（字二元组 Dice ≥ 0.5 视为同一条） | **0.51** |
| 两次发现**完全不重叠** | **50 / 145（34%）** |
| 两次发现条数相同 | 49 / 145（34%） |
| 条数相差 ≥ 3 | 32 / 145 |
| 节点级 reviewResult 相同 | 118 / 145（81%） |

节点级结论相对稳（81%），因为那是确定性层给的。**发现层是掷硬币**：同一份资料、同一个 prompt、
同一个模型，三分之一的情况下两次给出的发现集合没有任何一条能对上。
按节点差异很大：节点 5、7 接近 1.0，节点 4、16 只有 0.1。

对监检来说这意味着：今天看到的三条问题，明天重跑可能是另外三条。

## 四、这三件事，「大模型出题、Jev 作答」分别改变什么

### 1. 主张校验从「词像不像」变成「对不对」

大模型每条发现拆成主张，每条主张一道选择题，选项固定带「证据不足／不成立」，
Jev 拿**整节点全文**作答并给机率。实测：没资料它答证据不足 conf 1.00；坏 OCR 表格它
分类 conf 1.00；给了平台数据它判人证不符 conf 0.96。

这直接替换第二节那层子串匹配。640 条碎片误伤消失（因为问的是语义，不是词），
用词重合的假结论被抓出来（因为它看的是资料是否支持，不是词是否出现）。

**这是准确度收益最大的一处**：现在这层是零信号，换成有校准的信号。

### 2. 可复现性：决定固定下来，波动只剩「问什么」

Jev 固定版本、同题同答。剩下的波动来自大模型每次拆出不同的主张。
两条办法把这也压住：

- **主张以原子项为锚**：194 个原子项是固定的，每个原子项的三态题是常量，不由大模型出。
  这就是你最初的「固定审计清单做选择题」——它在这里的价值正是消除出题波动。
- 大模型额外发现的主张，作为增量题，低置信度的直接不进结果。

预期：节点级 81% 不变（本来就是确定性层），发现级从 0.51 往上走多少要影子运行量。
**不承诺到 1.0**：大模型出的增量题仍会变。

### 3. 67% 的降级变成有区分度的三态

现在 699 条降级是一刀切：引用不够就全判证据不足，里面混着「资料确实没有」和
「资料有但校验器没认出来」。Jev 的三态把这两种分开，并给出机率排序，
人工先看哪条有了依据。

## 五、不改变的，和会变差的

- 186 项确定性结论不动，节点级 81% 一致率的来源不动。
- 上下文必须整节点全文。实测唯一一次有数据还判错就是片段。
- 多人文件按人拆题。
- 大模型出的题如果本身是错的框架，Jev 在框架内作答；靠每题带「不成立」选项兜底，
  但这个兜底的可靠性没有单独测过，影子运行要专门看。

## 六、影子运行要回答的三个数

1. **主张确认率**：大模型主张里 Jev conf ≥ 0.70 支持的占比（对照现在 33% grounded）。
2. **抓错率**：Jev 打回的主张里，人工认定确实错的占比。这个数是它的净准确度收益。
3. **发现级复现率**：原子项锚定 + Jev 之后，同输入两次运行的软一致率（对照 0.51）。

三个数拿到之前，以上是有依据的预期，不是结论。

## 七、结论

只看准确度：**接，接在大模型发现层，主张以原子项为锚，Jev 作答。**

依据不是 Jev 有多好，是这一层现在有多空：三分之二发现被降级、校验器只认词不认理、
同输入重跑三分之一完全对不上。这三个数任何一个都足以说明这一层需要一个独立的、
有校准的判断源；Jev 是目前唯一实测过能提供它的。
