# 焊接节点（24–29）优化计划

> 日期：2026-09-06。依据：《研究-焊接材料设计节点审查原则》（法规/标准事实与代码差距）与《规则测试-焊接材料设计节点-测试项目3与4》（真实资料判定与规则反馈）。范围：节点 24 焊工资格、25 焊接工艺文件、26 焊材质量证明、27 焊材管理、28 管道组对、29 施焊参数/记录/焊缝标识，以及它们与设计（5–9）、管材（16/21）节点的联动。本文只做计划，不含代码。

## 0. 目标与验收口径

**目标**：让六条原则在焊接节点上变成可自动执行、可解释、可回溯到原件位置的判定，而不是模型自由发挥。

**验收口径**（用测试项目3/4 作回归样本，期望结论已在规则测试报告中给出）：
1. 节点 24 对 测试项目4 姜军 给出"GTAW、SMAW 两项均覆盖 20# Φ108×8 6G"，引用证书代号、工艺卡参数与 TSG Z6002-2026 表 A-6/A-7/A-8 的具体条目；对 测试项目3 给出"按 WPS 无背面保护气无人覆盖；赵相军/席俊杰 若现场充氩则覆盖；姜军 FeⅡ 不覆盖 FeⅣ；李卫伍 平台未返回焊接项目需人工核查"。
2. 节点 25 对 测试项目4 PQR HP/P-2023-01 给出"母材 Fe-1-1、T=7 覆盖 1.5~14、GTAW 焊缝金属 pWPS 写 ≤6 超出 2t=4（预警）、PQR 未按 2023 版复核（预警）"；对 测试项目3 给出"Fe-8-1 T=6 覆盖 3mm；位置 1G 为次要因素；背面保护气与焊工证书冲突"。
3. 节点 26 对 测试项目4 判"焊材证明书缺失，不符合"；对 测试项目3 判"证书缺熔敷金属力学/执行标准/生产日期，证据不足；JQ.TG304 与 WPS H06Cr19Ni10 需型号等效确认"。
4. 节点 29 在缺施焊记录时明确输出"焊口联合表无法构建，四链闭合失败"，并列出缺哪一类资料。
5. 每条发现都带 evidenceRefs（页码/bbox/原文）与规则条款号，正式审查可引用。
6. 单元测试覆盖覆盖表的每一行；测试项目3/4 的 OCR 快照作为端到端回归数据。

## 3. P1 节点 24 焊工资格

### 3.1 数据层：`business_packs/engineering_inspection_v1/welder_qualification.yaml`
- `editions`: `tsg_z6002_2010`（施焊日期 < 2026-08-01）、`tsg_z6002_2026`（≥ 2026-08-01；证书有效期内旧证按新表）。
- `methods`: SMAW/GTAW/GMAW/FCAW/SAW/PAW/OFW…，别名表（氩弧焊→GTAW，药芯气保焊→FCAW）。
- `materialCategories`: FeⅠ~FeⅣ 牌号清单（表 A-2 全量）+ NB/T 47014 类别→TSG 类别映射（Fe-1/3/4/5A→FeⅠ/Ⅱ，Fe-5B/6/7→FeⅢ，Fe-8/10→FeⅣ）；覆盖矩阵两版各一份。
- `positions`: 表 A-6 覆盖矩阵（含 5GX/6GX、板试件用于管件 D≥76、角焊缝/管板）。
- `thickness`: 表 A-7（T<12→2t；≥12→不限）、气焊、堆焊表 A-12。
- `diameter`: 表 A-8/A-10（<25→≥D；25~76→≥25；≥76→≥76；向下焊 ≥300→≥76）。
- `filler`: 表 A-3 覆盖链（Fef1/2/3/3J/4/4J/FefS）+ 焊材型号→Fef 类别映射（E4303→Fef3、E4315/E5015→Fef3J、E308-16→Fef4、E308-15→Fef4J、焊丝→FefS）。
- `processFactors`: 01/02/03/10/11/12/13/14/23/24 参与比较；`11→10 allowed`；FeⅢ 的 10 豁免；机动焊因素表。
- `backing`: 无(K) 覆盖有(K)；带(K) 只覆盖带衬垫/双面焊/角焊缝/不焊透接头；"后焊方法视为带衬垫"。

### 3.2 代号解析 `decode_welder_code` v2
- 模糊纠错表：`CTAF/CTAV/GTAV→GTAW`、`SHAV/SHAW/SMAY→SMAW`、`PTAV→GTAW?`（标记低置信）、`FetS/Fe1S/FefS`、`Fef3J/FefBJ/Fe13J`、`Fef4J/Fe14J`、`6C→6G`、`5FC/6FG`、`63/57→6G-3/57`；全角/罗马数字规范化；每段带 `confidence` 与 `rawSegment`。
- 结构校验：六段 + 工艺因素；板/管判别（有 `/` 为管）；(K) 提取；组合考试（"和"连接）拆成多项。
- 输出 `parseStatus: parsed | corrected | unsupported`，corrected 时在发现里提示"代号 OCR 已纠错，请核对原件"。

### 3.3 覆盖判定 `check_welder_work_coverage` v2
- 输入：焊口/管线事实（方法、母材牌号→类别、外径、壁厚、焊缝金属厚度按方法拆分、位置、是否向下焊、衬垫/打底、背面保护气、填充金属类型/焊材型号、极性）来自 WPS/工艺卡 + 管道特性表 + 施焊记录。
- 逐维度输出 `checks[]`（每项含规则条款：如 `TSG Z6002-2026 表 A-8`），任一 fail 即不覆盖；`evidence_insufficient` 只在关键输入缺失时。
- **WPS 联动**：工艺因素与衬垫取自 WPS/工艺卡而非证书自身；工艺卡"持证项目"文本与参数表矛盾 → 单独 `process_card_inconsistent` 预警。
- 组合工艺：GTAW 打底 + SMAW 盖面分别判定；后焊方法自动视为带衬垫；焊缝金属厚度按各方法层厚（工艺卡"层/道"表）估算，缺失时按"打底 ≤3mm、其余为壁厚减打底"保守估算并标注。
- 版本：按施焊日期选表；证书批准日期 < 2026-08-01 的旧证在 2026-08-01 后按新表。

### 3.4 三方比对与真实性
- 输入源优先级：平台记录 > 证书原件 OCR > 焊工清单；任何不一致生成 `roster_certificate_platform_mismatch` 发现（列三方值）。
- `check_certificate_validity` 保留（有效期覆盖施焊期）；新增"连续中断 6 个月能力验证"提示（需用人单位记录，缺失 → 需人工确认）。
- 平台"聘用单位"与施工单位不一致 → 预警级发现（待你决定是否升级）。
- 无效证据识别：非中文/测试用文件（如"AICheck Upload Verification"）→ `invalid_evidence`。

### 3.5 输出与展示
- 节点 24 卡片：每位焊工一行（姓名、证号、平台状态、项目代号、有效期）+ 每个焊口/管线一列的覆盖矩阵（✓/✗/?），点击展开逐维度依据。
- 发现模板：`焊工{姓名} {代号} 对 {管线} {方法} 覆盖/不覆盖：{维度} {实际} vs {证书范围}（{条款}）`。

### 3.6 测试
- 覆盖表逐行单测（2010/2026 各一套）；OCR 纠错单测（本次真实 OCR 串）；测试项目3/4 快照端到端；边界：D=25/76、t=12、5GX、FeⅢ 因素 10 豁免、组合考试拆分。

## 6. P4 焊口联合表（节点 29 为核心）

### 6.1 数据结构 `weld_joint_ledger`
- 主键：焊口号（施焊记录）；字段：管线号、规格、材质→类别、位置、方法（按层）、焊工代号/证号、焊材型号/规格/批号（按层）、WPS 号、PQR 号、管材炉批号（来自标志移植/管材证）、日期、电参数、道间温度、背面保护气、NDT 结果引用。
- 构建器：从 `welding_record` OCR 表 + `pipeline_summary`/管道特性表 + 焊工证/平台 + WPS/PQR + 焊材证/领用 + 管材证/标志移植 汇合；每条链记录来源证据链接。
- 无施焊记录时：以管线为主键生成"预期焊口"骨架，标注链缺失原因（缺施焊记录/缺领用记录/缺标志移植）。

### 6.2 判定 `evaluate_welding_process` v2
- 四链闭合矩阵：焊工链（调用 P1）、工艺链（P2）、焊材链（P3）、管材链（R16/R21）；每焊口输出 closed/broken/conflict。
