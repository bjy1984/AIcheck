## 先说一次纠错：初版清单是错的

初版列了 **21 份**。核实存储时发现其中 **13 份文件其实好好地躺在**
`/app/output/document_uploads/` 下——被判成「丢失」是两个**产品缺陷**造成的误判：

1. **worker 容器没挂 output 卷**（只有 API 挂了）。worker 里 `/app/output` 根本不存在，
   OCR/切片自然取不到任何 `local://` 原件。
2. **worker 的 `WORKSPACE_ROOT` 用目录层数倒推**（`parents[3]`）。容器里代码在
   `/app/apps/worker/`，往上三层是 `/`，于是路径解析成 `/output/...`——不存在。
   `routes.py` 早修过同款 bug（当时 66 个线上文件预览失效），worker 漏了。

两处都已修复（commit `a726496`、`917cee9`）。修复后重扫，丢失数从 21 降到 8，
**33 份文件恢复可读**。

> 这条记下来是因为：差点据此让用户白白重传 13 份资料。
> 判「文件没了」之前必须先确认**读文件的那条路径本身是对的**。

## 判据

同时满足才列入（`source_missing_scan.py`，跑在已修复的 worker 容器内）：

1. `storageKey` 是 `local://`（本批 8 份全部如此）；
2. 按**正确的** `WORKSPACE_ROOT`（`/app`）解析出的路径不存在；
3. OCR 抽出的可用文本 < 50 字符。

## 防止再发生

- worker 与 API 必须挂同一份 `output` 卷——已写进 `deploy_to_server.sh` 的 `recreate_worker`；
- 路径根目录一律走 `libs/workspace_paths.resolve_workspace_root()`，
  **不要再用 `parents[N]` 倒推**（由 `test_workspace_root_resolution.py` 钉住）；
- 注意 `docker-compose.deploy.yml` 里 api/worker 都没声明这两个卷——
  生产实际由部署脚本的 `docker run` 决定，compose 与生产已脱节，是独立的待办。
