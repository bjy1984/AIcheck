## 追加：把已入库的法规数值接进判定（2026-09-07 夜）

审计只查了「功能在不在」，没查「数据有没有被用上」。补做这一层时发现两处同样形状的缺口——
限值都已入库，但判定拿不到，于是永远停在「证据不足」：

| 判定 | 缺口 | 修法 |
|---|---|---|
| R16 质保书数值比对 | `evaluate_r16_quality_certificate_results` 要调用方传 `acceptanceLimits`，设计图纸上只写「GB/T 8163-2018 Q345B」，限值在标准里，没人做这一步 | 设计项没带限值时按「执行标准 + 牌号 + 质量等级」从 `pipeMaterialLimits` 推导；人工填的优先，查不到不猜 |
| R26 焊材证明书 | `evaluate_welding_consumable` 要 `productStandardProfiles`，`r24_r34_facts` 里那行永远取到空字典 | 从 `weldingConsumables` 生成，键按「标准号 + 型号」——同一标准下 E4303 与 E5015 的抗拉强度差 60MPa，只按标准号取会把合格的判成不合格，所以多型号标准的裸标准键被显式剔除 |

两处都有端到端用例：质保书抗拉 380（下限 410）判 failed；焊条抗拉 430（下限 490）判 failed。

扫完之后又找到第三处：

| 判定 | 缺口 | 修法 |
|---|---|---|
| R14 出厂检验项 | `execution.py` 里 `product_rules` 写死了只有 GB/T 12771-2019 一条，别的产品标准一律 `product_standard_rule_missing` | 从法规表读，六本管材标准都在；表里查不到时仍回落到原来那条，行为不退化 |

一条判定口径上的注意：只有标准正文里**逐根或按批强制**的项进 `requiredItems`；
「根据需方要求、经供需双方协商」的选项放在 `conditionalItems` 里，
拿它判不符合会冤枉人（GB/T 3087 的高温拉伸、GB/T 8163 的冲击都属这类）。

**这类缺口的扫法**：`grep -rhoE '"[a-z_]+_(missing|unavailable)"' libs/review_tools/` 列出全部
「缺数据就停」的理由码，挑出带 limit / profile / rule / standard 字样的，逐个看那份数据是不是
其实已经在法规表里。172 个理由码里这样的有 19 个，已处理 3 个，其余多数是真的缺证据（缺证书、缺记录），不是缺法规值。
