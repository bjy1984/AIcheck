## 如何測試

本機 `backend/.venv` 已能匯入 psycopg、temporalio、fitz；「任何 Python 都裝不全」不再適用。不要在正在服務的生產 API／worker 容器內跑 pytest。

```bash
cd backend
.venv/bin/python -m scripts.ruff_baseline
.venv/bin/python -m pytest --collect-only -q
.venv/bin/python -m pytest tests -q
```

整合測試需設定 `AICHECK_TEST_POSTGRES_URL` 指向專用測試 PostgreSQL，使用者必須能建立及刪除測試資料庫；不設定會有明確原因的環境跳過。不得填生產 DSN。本輪另外實跑 PostgreSQL，不把這些跳過當成整合驗收。

```bash
# 從倉庫根目錄，建立專用工作區及測試衍生鏡像
bash backend/scripts/run_tests_in_container.sh tests --collect-only
bash backend/scripts/run_tests_in_container.sh tests
```

預設主機 `aicheck-prod-new`，專用工作區 `/tmp/aicheck-tests-repair`。不要同時在同一工作區啟動兩輪同步／測試。權限、同步或測試失敗即停止，沒有「固定失敗數量可接受」模式。

GitHub `backend-quality.yml` 的 lint 和 test 是獨立工作，任何工作失敗都不能宣稱 CI 通過。test 工作包含 PostgreSQL、MinIO 保留版本及服務重啟、Temporal 重試與服務重啟驗證。
