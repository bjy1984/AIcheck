# 标准条款数据库固化实现

## 实现结论

当前工程已把固定标准条款接入现有 `aicheck_state` SQLite/PostgreSQL 持久化模型。YAML 仍是维护和发布源，节点预览与新发起的 AI 复核运行使用数据库中的版本化条款包。

数据库逻辑集合如下：

| 状态键 | 数据库 collection | 用途 |
|---|---|---|
| `standard_document_versions` | `standard_document_versions` | 标准文件与知识文件版本 |
| `standard_clause_references` | `standard_clause_references` | 可复用的标准条款引用 |
| `standard_clause_locators` | `standard_clause_locators` | PDF 页级定位 |
| `standard_clause_packages_db` | `standard_clause_packages` | 69 个版本化节点条款包及预编译预览 JSON |
| `standard_clause_package_items` | `standard_clause_package_items` | 节点包与主/专业条款绑定 |
| `project_node_clause_packages` | `project_node_clause_packages` | 具体项目节点绑定的条款包版本 |
| `review_run_clause_snapshots` | `review_run_clause_snapshots` | ReviewRun 使用的不可变条款快照 |

## 本地发布

未指定 `AICHECK_SQLITE_PATH` 时，同步和审计脚本默认使用忽略提交的 `data/aicheck.local.sqlite3`，避免修改仓库内可能由 Git LFS 管理的数据库文件。

```bash
cd backend
AICHECK_ENABLE_DEMO_DATA=true \
  .venv/bin/python scripts/sync_standard_clause_artifacts.py --apply --json
```

指定实际运行库：

```bash
AICHECK_SQLITE_PATH=/absolute/path/aicheck.sqlite3 \
  .venv/bin/python scripts/sync_standard_clause_artifacts.py --apply --json
```

PostgreSQL：

```bash
AICHECK_DATABASE_URL=postgresql://... \
  .venv/bin/python scripts/sync_standard_clause_artifacts.py --apply --json
```

导入是按 `businessPackId@businessPackVersion` 幂等替换，同一版本重复执行不会产生重复记录，历史版本不会被删除。

## 运行读取

项目创建或重新应用业务包时，系统为每个有条款包的项目节点写入 `project_node_clause_packages`。节点标准接口按以下路径读取：

```text
projectId + nodeId
        ↓
project_node_clause_packages
        ↓
standard_clause_packages.compiledPayload
        ↓
knowledgeFileId + documentVersionId + locator
        ↓
/api/knowledge/files/{id}/original?disposition=inline#page=N
```

如果工程业务包声明了固定条款包，但项目节点没有数据库绑定，标准预览和 AI 复核会失败关闭，不回退为动态检索条款。

## ReviewRun 冻结

发起 AI 复核时，AI Run 取得项目节点当前绑定的 `clausePackageSnapshot`。创建 ReviewRun 时，再写入独立的 `review_run_clause_snapshots` 记录。Review Worker 将固定条款快照加入规则执行关联 ID 和 Prompt 输入，不再用最新 YAML 条款替换历史依据。
