# 业务节点与固定标准条款绑定方案

## 1. 结论

现有 69 条工业管道监检业务规则，以 `files/checklist.docx` 的 1-69 项为唯一编号基准；R01-R68 主体结构与《TSG D7006—2020 压力管道监督检验规则》附件 D 的 D2.1～D2.15 基本同序，R69 依据第 2.2.4 条及附件 G。本次已把直接监检条款作为每个业务节点的固定主依据，并逐节点补充 GB/T 20801.1、NB/T 47013、TSG 31 等专业执行条款。运行时不再让 LLM 检索、选择或猜测条款。

本次已形成并发布 69 条主绑定、69 个节点条款包、194 个原子审核项和 33 份标准目录记录，并为 120 条专业条款引用补齐 211 个 PDF 页级定位。R10 已纠正为直接绑定 TSG 31—2025 第 1.9(3)，并以第 3.1.3.1 作为设计文件专业补充依据；R15 已直接绑定 D2.4.1(4)，并以第 1.10、2.2.1.5 作为专业补充，与 R19 境外牌号材料规则分离；R16 已覆盖 8 类产品标准路由，R17-R18 已补齐到货验收和条件复验/NDT条款；R24-R34 已补齐焊接、焊材、组对、返修及热处理专业条款与专用 Tool 绑定；R69 保留为人工评价边界。

## 2. 现有工程情况与本次调整

现有 `rules.yaml` 已有 `referencedStandards`，但它只绑定到标准文件，存在重复引用，也没有条号、页码、标准版本、核验状态和发布状态，运行时仍可能依赖检索或 LLM 判断依据。本次新增独立的 `standard_clause_bindings.yaml`，并让业务包加载器读取和校验该配置。

配置采用四层结构：

- `standardCatalog` 管标准文件、版本、知识库文件 ID 和文档版本。

- `standardClauseBindings` 管“规则/节点—标准—条款”的关系，以及主/补充依据、适用条件、原文定位、核验状态和生命周期。

- `standardClausePackages` 管每个节点的主绑定、专业条款、适用条件、确定性决策模型和版本快照策略。

- `atomicChecks` 管从 `业务规则.md` 拆出的可独立执行、可引用证据的原子审核项。

## 5. 绑定关系如何维护

绑定记录至少包含：`bindingId`、`ruleId`、`sourceRuleId`、`nodeId`、`standardRef`、`clauseNo`、`bindingRole`、`applicability`、`knowledgeFileId/documentVersionId`、`sourcePage/startPage/endPage`、`sourceLocatorId/locators`、`verificationStatus`、`lifecycleStatus`。组合条款存在不连续落点时，必须拆成多个 locator。后续落数据库时，还应补充 `effectiveFrom/effectiveTo`、`supersedesBindingId`、`reviewer/reviewedAt` 和条文快照哈希。

状态分开管理：

- 核验状态：`candidate` → `source_verified` → `rejected`。

- 生命周期：`draft` → `published` → `retired`。

只有 `published + source_verified` 才能被正式复核运行使用；草稿和候选只在维护后台可见。每次 AI 复核启动时，把实际使用的绑定 ID、标准版本、条号和文档版本冻结进 ReviewRun 快照，避免规则更新后历史结果无法复现。

维护界面建议以业务节点为左侧树，右侧展示主依据和补充依据。编辑条款时必须从标准目录选择标准与具体条款，禁止自由文本直接发布；换版时创建新绑定并用 `supersedesBindingId` 指向旧绑定，不覆盖历史记录。

## 6. 运行时调用方式

1. 根据当前业务节点取得已发布规则。
2. 由确定性服务读取该规则已发布的固定条款绑定，不调用 LLM 选条款。
3. 按适用条件过滤补充条款，例如材料类别、检测方法、管道级别、是否采用境外标准。
4. 把条款快照、证据抽取结果和业务规则工具的结构化结果一起交给 LLM。
5. LLM 只负责解释冲突、组织可审计摘要和提出补证建议；确定性数值与逻辑结论直接使用工具结果。

## 7. 后续维护边界

六批条款已经完成。后续工作属于持续维护，不再是本次绑定缺口：

1. 标准换版时新增目录版本和绑定，不覆盖历史 ReviewRun 快照。
2. 对已完成 PDF 页级定位的 `visual_verified` 扫描件，可按展示需要继续补录文本块或坐标级高亮，不再缺少原文跳转页。
3. 新增产品标准或检测方法时，以条件分支扩展 `professionalClauses`，不得改变不相关项目的适用结论。
4. 每次发布前运行独立审计脚本、业务包专项测试和全量回归。
