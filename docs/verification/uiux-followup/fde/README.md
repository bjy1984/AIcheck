# FDE 後續修復

最終版 `dist-uiux-followup-final` 已完成 **16/16 主路由、21張修後原圖及3張修前對照**，逐張目視確認。另補1280px規範表、900px資料卡片、規範詳情與實際能力狀態；瀏覽器error紀錄為空。

## 已重現

- 規範清單在1280×720只有檔名、切片、章節與水印，狀態／問題被擠到可見區之外，必須橫向捲動才看到；[修前畫面](before-standards.jpg)。
- 項目總覽OCR零任務仍標「正常」，柱狀圖用36／92／96等固定數字充當健康評分；[修前畫面](before-capability.jpg)。
- 真實API診斷「API 服务未配置 OCR 服务地址（AICHECK_OCR_BASE_URL）。」經多輪字串替換後，OCR文字重複且識別碼消失；[修前畫面](before-ocr-diagnosis.jpg)與[原函式重現](reproduction.txt)。

## 修改

- 規範表保留五個主要欄位：檔名、索引進度、治理狀態、問題、查看／校對。長檔名換行；索引版本仍可在原有詳情查看。1100px以下切換既有資料卡片，避免操作與狀態被寬表遮蔽。
- 能力區改以真實任務完成數、向量化文件、章節數與通過門禁數表示狀態，移除推算評分。任務未知／未完成、缺資料、缺門禁、存在問題均不視為正常；沒有文件不再捏造一份分母。處理清單使用全寬，長狀態換行。
- 診斷格式化只對原始文字執行一次token替換，不再翻譯剛產生的標籤。已帶中文說明的括號識別碼保留，未知ID與模型／任務代碼不隨意改寫。

## 檢查

`fdeFollowup.test.ts`執行實際元件內格式化與computed程式，覆蓋真實API診斷、環境變數、一次替換、不破壞未知ID、任務完成精確匹配、缺資料／空任務／執行中／失敗、未知門禁與全部有效條件。全站單元測試、型別與建置結果見上層verification.json。
