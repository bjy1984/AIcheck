# 通用審查與共用外框的內容取捨

| 區域 | 核實的干擾 | 本輪處理 | 保留理由 |
| --- | --- | --- | --- |
| 通用審查首屏 | 專案、節點、發現、引用數在頂欄/摘要/專案卡/三張品質卡重複 | 移除重複數字卡，直接呈現專案選擇與節點資料進度 | 節點與發現清單保留實際件數、狀態及操作 |
| 通用頁左下角 | 平台語義、復用邊界、遷移方式是開發說明 | 移除整個平台邊界區塊 | AI草稿與正式人工結論區分仍由發現狀態與意見提供 |
| 通用頁角色內容 | 建設/施工方被展示核驗置信度、內部節點碼、規則及證據引用計數 | 建設/施工只看進度、發現、引用原文與人工意見；監檢/管理保留核驗欄位 | 信心值有助核驗人員判斷需檢查的內容，不是業務使用者的工作指標 |
| 發現詳情 | 每條原文下方都呈現證據ID及原始規則識別碼 | 規則與引用編號限審查/管理，且按需展開 | 任何角色仍可讀原文、頁碼與正式意見，未刪證據 |
| 頂欄搜尋/任務 | 通用頁硬編碼使用admin範圍 | 按登入角色及所選專案傳正確範圍 | 搜尋、任務仍遵循後端權限 |
| 任務中心 | 每張卡固定顯示Operation ID、模型、調用次數、費用、心跳 | 業務角色移除；admin/FDE放執行詳情中 | 保留進度、時間、等待、失敗、下一步與重試/取消 |
| 共用外框 | 無內容時仍可能留下摘要與邊界入口 | 空rightCards/boundaryRows不渲染入口及抽屜 | 有實際診斷內容的專頁仍保留入口 |

逐頁實測後補充：業務角色任務類型使用「資料處理」，未知類型不暴露內部代碼；跨小時／天的耗時以相應單位顯示。切換路由或進入沒有診斷卡的頁面會關閉上一頁摘要，避免舊抽屜在下一個專頁重新彈出。通用發現表的人工確認欄加寬，完整呈現狀態標籤。

文件詳情按角色選擇預設資訊：建設／施工／無損檢測以文件資訊與歷史版本為主；監檢／管理／FDE保留字段、表格、印章與原文核驗。已確認的「缺少可追溯識別結果」警告改用工作語言，保留其異常含義與重新識別建議。

本次僅調整內容呈現及角色入口回退，不改審查流程或後端授權。
