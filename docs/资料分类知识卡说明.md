# 资料分类知识卡说明

## 目的

`backend/config/material_classification_knowledge.json` 是压力管道监检资料分类的人工可审计知识文件。它回答“这是什么文件”，不直接回答“文件是否满足监检要求”。

分类知识与业务审查证据必须分开：

- 分类知识使用标题、文件结构、签发主体、对象和语义边界识别资料类型；
- `material_review_points.json` 中的 `evidenceItems` 用于分类完成后的节点审查、字段定位和合规判断。

## 知识卡结构

每个 `materialTypeCode` 对应一张知识卡：

- `classificationDefinition`：资料类型定义；
- `documentPurpose`：文件业务用途；
- `titlePatterns`：常见标题或表头，不要求逐字一致；
- `requiredSignals`：分类成立必须获得的核心信号；
- `supportingSignals`：提高可信度的辅助信号；
- `negativeSignals`：出现时应排除或降低该类型置信度的信号；
- `confusableWith`：易混淆类型和可解释区分方法；
- `basisLevel`：`standard_supported` 表示存在直接标准条款支持，`business_defined` 表示目前主要来自业务映射和审查规则整理；
- `sourceRefs`：知识来源和定位信息。

一个 OCR 文档可以同时满足多张知识卡。例如一个资料包同时包含产品质量证明书、制造许可证和出厂检验报告时，应输出多个 `materialTypeCode`，不能强制单选。

## 当前覆盖

- 60 张资料类型知识卡；
- 11 张具有直接标准条款来源；
- 49 张目前按业务规则和人工分类口径整理；
- 所有卡片名称和所属大类必须与 `material_review_points.json` 一致。

“业务整理”并不表示内容无效，而是表示现有标准库尚未把该文件类型的定义、格式或必要内容整理为可直接引用的分类条款。后续补充标准来源时，应同时修改 `basisLevel` 和 `sourceRefs`。

## 人工复核重点

复核每张知识卡时依次确认：

1. 定义描述的是文件身份，而不是业务合规结论；
2. 必要特征足以区分标题相似的文件；
3. 排除条件不会错误排除合法的组合资料包；
4. 易混淆类型列出了真正有区分价值的边界；
5. 标准条款编号能够回到标准原文；
6. 不将文件名、目录名或上传入口作为分类依据。

## 校验

在 `backend` 目录执行：

```bash
.venv/bin/python scripts/validate_material_classification_knowledge.py
```

校验器检查：60 类型完整覆盖、编码唯一、名称与大类一致、必要字段非空、易混淆编码合法，以及标准支持卡片确实提供标准来源。
