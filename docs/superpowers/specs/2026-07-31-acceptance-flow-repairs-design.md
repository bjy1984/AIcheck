# 完整验收流程修复设计

## 1. 目标

修复完整测试资料包在真实界面验收中暴露的四条业务断链，使现有项目 `QX201903S-13-Y` 能按照 `files/测试说明.md` 完成以下操作：

1. 无损检测机构先登记底片结构化信息，再上传影像，并在检测报告中关联底片。
2. 监检人员在 R21、R24、R28、R30、R44、R48–R53、R69 上传自己形成的现场或评价证据。
3. R69 将质量保证体系评价工作流记录作为必传证据，但最终评价结论只能由监检人员人工保存。
4. 施工方提交文件时提交该文件实际关联的全部待提交节点，提交后列表与节点挂载状态一致。

不放宽报告与底片的追溯要求，不根据文件名自动生成不可核验的业务事实，也不允许系统代替监检人员形成 R69 评价结论。

## 2. 根因

### 2.1 NDT 底片

后端已有 `POST /projects/{projectId}/ndt/films` 和前端 `handleCreateNdtFilm`，但 `NdtWorkflowPanel.vue` 的“底片与影像资料”只触发通用文件上传，没有可操作的底片登记表单。通用上传只生成 `DocumentAsset`，不会生成 `NdtFilm`，因此检测报告抽屉看不到可关联底片。

### 2.2 监检资料

后端已有节点附件上传路由，但前端既没有对应 API 封装，也没有监检专用按钮。当前通用上传还不会把完成后的文档自动绑定并提交到当前监检节点。

### 2.3 R69

`nodes.yaml` 中 R69 只有 `project:view`，没有 `requiredMaterials`。节点运行时因而显示 0 项资料要求，工作流记录无法成为人工结论的正式证据。

### 2.4 施工方提交状态

`handleSubmitProjectFile` 固定使用当前活动节点，而不是文件的全部待提交挂载。用户在关联对话框选定多个节点后点击文件行“提交”，实际可能只提交当前节点；目标节点仍保留“草稿挂载”，列表却给出成功提示。

## 3. 方案选择

采用“恢复完整领域流程”方案：

- NDT 显式登记底片元数据，保留结构化追溯链。
- 监检资料通过专用入口完成上传、绑定和提交。
- R69 使用正式资料要求配置，并保持人工决策边界。
- 施工方按文件的真实挂载集合提交。

不采用以下方案：

- 根据文件名自动生成底片记录：文件名不足以证明焊口、方法和检测结论。
- 允许 RT 报告不关联底片：会破坏现有证据完整性门禁。
- 仅修改显示文案：不能修复后端状态与实际挂载的断裂。

## 4. 组件与数据流

### 4.1 NDT 底片登记

新增独立的底片登记对话框，字段至少包括：底片编号、焊口编号、检测方法、关联管线、报告号、底片包号、影像文件名、执行标准、评定级别、检测人员和复核人员。

“底片与影像资料”提供两个明确动作：

1. “新增底片编号”打开结构化登记对话框，提交到现有 NDT film API。
2. “上传底片/影像”继续使用通用上传抽屉，保存 JPG 等原始影像。

登记成功后刷新 `ndtFilms`；检测报告上传抽屉立即显示这些底片并允许多选关联。影像文件通过 `imageFileName` 与结构化底片记录保持可核对关系。

### 4.2 监检资料上传

在监检节点页顶部增加“上传监检资料”按钮，仅 `inspection` 角色、节点视图和可写项目可见。

操作流程：

1. 调用节点附件上传 API 创建上传会话，文件强制标记为“监检现场补充证据”。
2. 上传二进制并完成会话。
3. 使用完成结果中的 `documentId` 和 `documentVersionId` 创建当前节点绑定，`usage` 为“监检资料”。
4. 立即提交这些新绑定，形成快照、待办和审计记录。
5. 刷新项目文件库、节点包和提交历史。

任一步失败时保留上传抽屉和可重试错误；不得提示整体成功。已上传但未绑定的文档仍保留在项目文件库，重试时按文档 ID 幂等绑定，避免重复业务记录。

### 4.3 R69 资料与人工评价

R69 增加一个必传资料项：

- 编号：`REQ-69-01`
- 类型：`quality_system_document`
- 名称：施工单位质量保证体系实施状况评价工作流记录
- 责任方：监检人员现场补充
- 要求：覆盖当前项目、R01–R68状态、评价人员、评价日期、评价结果和签发信息

上传的 XLSX 通过监检专用入口绑定 R69。人工结论仍沿用 confirmed evidence 门禁；AI 只校验证据完整性，不能自动保存“满足要求”。

### 4.4 施工方提交

文件行“提交”从该文件的 `bindings` 中选择状态为“草稿挂载”或“需补正”的挂载，提取全部 `bindingIds` 和 `nodeIds` 后一次提交。若文件没有挂载，则提示先关联审核环节，不再隐式提交当前节点。

列表状态采用全部挂载聚合：

- 存在草稿或需补正挂载：待提交/补正。
- 全部挂载均已提交或通过：已提交。
- 没有挂载：未关联。

## 5. 权限与安全

- NDT 底片登记继续要求 `ndt:film-create`。
- 监检资料上传要求 `file:upload`，绑定要求 `file:bind`，提交要求 `submission:submit`，并受项目成员节点范围限制。
- 建设单位和 FDE 不显示业务上传入口，后端写请求继续返回 `FORBIDDEN`。
- 保持 `rules.yaml` 与标准条款包中 R69 的 `automatedDecisionAllowed: false` 不变，并增加回归断言，防止人工评价边界被后续配置变更破坏。

## 6. 测试设计

### 6.1 后端契约测试

- 监检节点附件上传会话保留节点和资料类别上下文。
- 完成上传后可绑定并提交到当前节点，来源单位和操作者正确。
- 非监检角色和越权节点请求被拒绝。
- R69 返回 `REQ-69-01`，上传后资料齐全度由 0/1 变为 1/1。
- R69 没有 confirmed evidence 时不能保存“满足要求”。

### 6.2 前端测试

- NDT 面板分别触发“新增底片编号”和“上传底片/影像”。
- 底片登记成功后报告抽屉可以选择对应 film ID。
- 监检角色在节点页看到上传按钮，其他角色看不到。
- 监检上传按“创建会话→上传→完成→绑定→提交”顺序执行。
- 施工方文件提交使用该文件的全部待提交绑定，而不是活动节点。
- 文件状态聚合对未关联、部分提交、全部提交分别给出正确结果。

### 6.3 页面回归

使用现有六类账号和现有测试项目验证：

1. NDT 登记至少一个底片并成功创建关联报告。
2. 监检在 R21 上传 JPG，在 R69 上传 XLSX。
3. 确认 JPG 无 OCR 时仍可提交并由人工核验。
4. 确认 R69 资料显示 1/1，人工结论未被自动生成。
5. 施工方新建一个多节点挂载文件并提交，所有目标节点均显示“已提交”。

## 7. 完成标准

- 四个回归用例均先失败、修复后通过。
- 后端相关测试、前端单元测试、类型检查和构建全部通过。
- 真实浏览器按 `files/测试说明.md` 能完成 NDT 报告关联、12个监检节点上传入口、R69证据上传及施工方多节点提交验证。
- 不新增跨角色业务权限，不降低证据或人工结论门禁。
