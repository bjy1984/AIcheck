# 无损检测资料页面业务化文案设计

## 目标

将无损检测资料上传与逐文件审批页面中的系统实现术语改为业务人员可理解的表达。节点编号继续作为内部数据关联字段使用，但不得出现在该页面、上传抽屉、规则调整弹窗、操作结果或校验错误中。

## 展示规则

1. 页面不得向用户展示“原子资料”“原子资料类型”“规则挂载”等实现术语。
2. “原子资料类型”统一改为“资料类型”；“规则挂载”统一改为“适用业务规则”。
3. 业务规则仅显示完整业务名称，不显示 `R35`、`R36`、`R37/R42`、`35–42` 等编号。
4. 上传入口表删除与“业务规则”重复的“默认挂载”列。
5. 上传抽屉和规则调整弹窗以完整业务名称作为选择项，内部仍提交原有节点编号。
6. 已上传文件列表的规则列显示完整业务名称；一个文件关联多项规则时逐项展示名称。
7. NDT 专用接口返回的校验消息、待办标题及操作审计名称使用“无损检测资料”“适用业务规则”等业务表达。

## 业务规则名称

- 35：无损检测机构施工现场质量保证体系的实施
- 36：无损检测方案
- 37：检测过程中发现问题的处理
- 38：无损检测人员资格证、执业注册证及持证合格项目
- 39：无损检测工艺文件
- 40：无损检测记录、报告
- 41：射线检测底片抽查
- 42：射线检测现场抽查

编号仅用于本说明中明确映射关系，不作为任何用户界面文案。

## 页面结构调整

- 区块标题使用“无损检测资料上传”。
- 上传入口表保留“资料类型、业务规则、已上传、操作”。
- 上传说明使用“系统自动关联适用的业务规则，可在上传前调整；每个文件上传后单独保存为草稿”。
- 文件列表使用“资料类型、适用业务规则、OCR、审批状态”等列名。
- 规则调整弹窗标题使用“调整适用业务规则”，并说明提交审批后不能再调整。

## 测试与验收

1. 目录测试验证 35–42 均有完整业务名称，且名称不含 `R+数字`。
2. 静态文案测试验证 NDT 页面和上传抽屉不包含“原子资料”“规则挂载”及面向用户的 `R+数字`。
3. 后端契约测试验证 NDT 专用错误提示不再包含“原子”或“规则挂载”。
4. TypeScript、ESLint、Stylelint 和相关后端测试全部通过。

## 非目标

- 不修改数据库字段、接口字段、节点编号或审批状态机。
- 不修改其他业务模块中具有独立含义的 R12、R19 等内部功能名称。
- 不改变逐文件草稿、规则调整、OCR 异步处理和单文件审批行为。
