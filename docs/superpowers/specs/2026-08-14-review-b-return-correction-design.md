# B 版退回补正与补充资料设计

## 目标

在 AI 复核 B 版右侧提供独立的“退回补正”操作。该操作与 ReviewRun 完全独立，并由后端一次事务写入正式“需补正”人工结论、补正或补充资料单、节点和资料状态、责任方待办及审计记录。

## 交互

- “最终人工结论”区域保留现有保存按钮，并增加独立的“退回补正”按钮。
- 点击按钮打开弹窗，不要求用户先保存“需补正”结论。
- 有当前节点“已提交”资料时，弹窗进入 `return_correction` 模式：列出全部可退回资料，默认全选，允许取消部分资料。
- 没有可退回资料时，按钮仍可点击，弹窗进入 `supplement_request` 模式：从 `evidenceReadiness.missingRequirements` 生成需要提交的资料清单，默认全选，允许取消、补充说明和手工增加资料要求。
- 若系统没有识别出缺失项，用户必须手工填写至少一项资料要求。
- 两种模式均要求填写具体原因和处理要求。默认使用当前人工复核意见，用户可修改。
- 确认前展示模式、资料数量和责任方；成功后刷新工作台并将右侧结论展示为“需补正”。

## 工作台投影

`review-workspace` 增加：

- `permissions.canReturnCorrection`：当前用户是否具有退回补正权限。
- `returnableBindings`：当前节点中状态为“已提交”的资料绑定，包含绑定 ID、文件名、资料类型、资料分类和状态。
- 现有 `evidenceReadiness.missingRequirements` 作为补充资料候选来源，不再重复维护第二份缺失清单。

权限与候选资料分开表达。没有 `returnableBindings` 不会禁用按钮，而是触发补充资料模式。

## API 扩展

复用 `POST /api/projects/{projectId}/inspection/nodes/{nodeId}/actions/return-correction`。

B 版新增可选请求字段：

- `opinion`：正式人工意见；传入时后端固定按“需补正”创建节点人工结论。
- `supplementRequirements`：补充资料项，每项包含稳定的 requirement/material 标识、显示名称和人工说明；手工项使用客户端生成的唯一 ID。
- `mode`：`return_correction` 或 `supplement_request`，后端根据有效资料绑定和补充资料项再次校验，不能依赖客户端声明绕过约束。

兼容规则：

- 原工作台继续只传 `reason + bindingIds + evidenceLinkIds`，行为不变。
- `return_correction` 必须至少包含一份属于当前节点且仍为“已提交”的资料，并存在有效提交记录。
- `supplement_request` 必须没有待退回资料绑定，并至少包含一项当前节点缺失要求或非空手工资料要求。
- 空任务、跨节点资料、过期资料状态和伪造的缺失要求均被拒绝。

响应增加 `rectificationType` 和可选的 `opinion`。

## 原子事务

扩展现有幂等 mutation，在同一个 `produce` 中完成：

1. 校验角色、节点范围、项目 etag、模式、原因和资料范围。
2. 创建 `ReviewOpinion`，结果固定为“需补正”，保存意见和适用的证据引用。
3. 创建 `Rectification`：退回模式保存 `bindingIds`；补充模式保存 `supplementRequirements`。
4. 退回模式把所选 binding 状态改为“需补正”；补充模式不修改不存在的 binding。
5. 把节点状态改为“需补正”。
6. 创建施工方或 NDT 待办。
7. 写入审计记录并返回统一结果。

任一步骤失败均不提交部分数据。重复幂等请求返回同一结果，不重复创建结论、补正单或待办。

## 责任方

- 退回资料全部属于 NDT 原子资料分类时分配给 NDT，否则分配给施工方。
- 补充资料要求全部属于 NDT 分类时分配给 NDT，否则分配给施工方。
- 混合资料要求分配给施工方，避免拆成多个隐式任务；多责任方拆单不在本次范围。

## 错误处理

- 无权限：前端隐藏或禁用操作，后端返回 403。
- etag 冲突或候选资料状态已变化：保留用户填写的原因，刷新工作台候选项并提示重新确认。
- 没有可退回资料：自动切换补充资料模式，不返回“当前节点没有可退回资料”错误。
- 没有系统缺失项：显示手工资料要求输入框，至少一项非空才能提交。
- 后端业务错误通过现有 `getAicheckErrorMessage` 展示，不改变 ReviewRun。

## 测试

- 工作台投影返回权限、可退回 binding 和缺失要求。
- 有资料时默认全选，允许部分退回。
- 无资料时按钮可用并生成补充资料请求。
- 缺失项默认全选，支持手工补充；空补充任务被拒绝。
- B 版一次请求原子生成“需补正”结论、补正单、节点/资料状态、待办和审计。
- 失败与并发冲突不产生部分写入；幂等重试不重复写入。
- ReviewRun 状态和 `humanDecision` 不变。
- 原工作台旧请求合同保持通过。
- 施工方与 NDT 待办归属正确。

## 非目标

- 不修改 ReviewRun 状态机或 human-decision API。
- 不自动启动或取消 AI 复核。
- 不把混合资料拆成多个补正单。
- 不改变施工方/NDT 反馈补正单的既有后续流程。
