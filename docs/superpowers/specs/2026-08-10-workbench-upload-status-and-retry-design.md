# 施工方与无损检测工作台上传状态及失败重试设计

## 背景与目标

施工方和无损检测机构工作台当前会直接展示 OCR、切片、向量化等内部处理阶段，并且部分入口允许文件在后台处理未完成时提交审批。业务用户不需要理解这些技术阶段，只需要知道文件是否仍在上传处理、是否可提交，以及失败后如何恢复。

本次改造将两个工作台统一为三种面向用户的状态：

- `上传中`：文件已进入系统，但任一内部处理阶段尚未完成。
- `上传成功`：OCR、切片和向量化全部完成，文件可以进入下一步提交。
- `失败重新上传`：任一内部处理阶段失败。该状态可点击，并在不要求用户重新选择本地文件的情况下重新处理原文件。

本次不修改 FDE、知识库等面向技术或运维人员的页面；这些页面仍可展示详细处理阶段。

## 状态模型

工作台继续消费后端现有的 `currentOcrStatus`、`sliceStatus` 和 `vectorStatus`，但通过共享的业务状态映射隐藏内部细节。

映射优先级如下：

1. 任一阶段包含失败状态时，返回 `失败重新上传`。
2. OCR 未完成、切片未完成或向量化未完成时，返回 `上传中`。
3. OCR 为 `已识别`、`人工修正` 或 `抽取不完整`，切片为 `已切片`，向量化为 `已向量化` 时，返回 `上传成功`。
4. 缺失、未知或尚未达到完整成功条件的状态按 `上传中` 处理，避免错误开放提交。

`抽取不完整` 仍可继续切片与向量化；只有整个流水线完成后才显示 `上传成功`。

## 用户交互

### 施工方工作台

项目文件库的“处理状态”列展示统一业务状态：

- `上传中` 使用进行中样式，提交按钮禁用。
- `上传成功` 使用成功样式；文件业务状态也允许提交时，提交按钮启用。
- `失败重新上传` 使用危险/可操作样式，并以按钮形式展示。点击后调用重试接口。

若文件业务状态本身不允许提交，例如已经提交或已作废，即使上传成功也不会重新开放提交。

### 无损检测机构工作台

“已上传资料”表格不再直接显示 `currentOcrStatus`，改为同一套统一业务状态。现有“OCR 不影响提交”的说明改为“上传处理成功后方可提交”。

提交审批按钮同时满足以下条件才启用：

- 文件审批状态为草稿或需补正；
- 文件有可提交的挂载关系；
- 统一上传状态为 `上传成功`。

失败状态同样显示可点击的 `失败重新上传`。

### 重试反馈

点击 `失败重新上传` 后：

1. 前端立即进入请求加载态，防止重复点击。
2. 后端确认当前用户对项目有写权限、文件属于该项目、当前版本存在且处理状态确实失败。
3. 后端确认对象存储中的原始文件仍然存在。
4. 后端清理或失效当前版本的失败处理中间结果，将三个阶段状态重置为待处理状态，并重新派发完整文档处理任务。
5. 前端刷新项目资料，状态显示为 `上传中`。
6. 后台处理完成后，现有数据刷新机制将状态更新为 `上传成功`。

若原始文件已丢失，接口返回明确错误：“原文件已不存在，请重新选择本地文件上传。”前端保留失败状态并显示错误，不创建空任务。

## 后端接口

新增项目文件级接口：

`POST /api/projects/{projectId}/documents/{documentId}/retry-upload`

请求不需要文件内容。接口复用文档当前版本的对象存储地址，并重新派发完整处理流程。

接口要求：

- 使用现有 mutation guard、项目及角色权限校验。
- 只允许施工方和无损检测机构在文件处理失败时调用。
- 支持 `Idempotency-Key`，相同请求不得并发创建多个重试任务。
- 返回当前文档 ID、版本 ID、重置后的业务状态和新派发的任务信息。
- 记录审计事件，说明操作者、文档、版本和重试时间。
- 不创建新文档或新版本，不复制对象存储内容。

该接口名称沿用用户语言中的“重新上传”；实际行为是复用已保存原文件并重新执行上传后的完整处理流程。

## 数据与一致性

重试沿用原 `documentVersionId`，避免同一内容产生虚假版本。重试前应移除或失效该版本的旧 OCR 结果、切片、向量以及关联的失败任务结果，防止新旧结果混用。已有文件绑定关系、资料类别、业务规则关联和审批草稿保持不变。

提交接口仍需在后端执行上传成功校验，不能只依赖前端按钮禁用。这样可以防止旧页面、并发状态变化或直接 API 调用绕过限制。

## 错误处理

- 非失败文件触发重试：返回业务校验错误，不重复派发任务。
- 原文件不存在：提示重新选择本地文件上传。
- 已提交或只读项目：按现有权限/状态规则拒绝。
- 派发失败：文件保持失败状态；不得先改为可提交状态。
- 重试请求已受理但前端刷新失败：显示请求已受理提示，用户刷新页面后可继续查看状态。

## 测试策略

### 前端单元测试

- 所有排队、OCR、切片、向量化中的内部状态统一映射为 `上传中`。
- 完整成功状态映射为 `上传成功`。
- 任一阶段失败映射为 `失败重新上传`。
- 未知或缺失状态不会误判为成功。
- 提交资格只有在业务状态可提交且上传成功时成立。

### 前端组件/静态检查

- 施工方表格失败状态可点击并触发重试事件。
- 无损检测表格使用统一状态而非原始 OCR 状态。
- 两个工作台在上传中和失败时禁用提交，在上传成功时按业务状态启用。
- 页面不再向施工方和无损检测机构展示 OCR、切片、向量化过程文案。

### 后端测试

- 失败文件可复用当前版本的存储对象并派发一次完整处理任务。
- 非失败文件、跨项目文件、无权限角色和只读项目被拒绝。
- 原对象不存在时不派发任务。
- 相同幂等键不会创建重复任务。
- 重试保留绑定和版本，清理旧处理中间结果，并重置内部状态。
- 文件未达到完整成功状态时，施工方和无损检测提交接口拒绝请求；完整成功后允许提交。

## 验收标准

- 施工方和无损检测机构工作台只显示 `上传中`、`上传成功`、`失败重新上传` 三种处理状态。
- OCR、切片、向量化等技术过程不再出现在这两个角色的文件上传状态区域。
- 文件仅在 `上传成功` 后可以提交。
- `失败重新上传` 可点击，且无需用户重新选择本地文件。
- 点击后只复用原文件重新处理，不产生重复文件或虚假版本。
- 原文件丢失时给出明确的重新选择文件提示。
