# 角色测试文件目录设计

## 1. 目标

在不修改既有完整资料包的前提下，新建 `files/角色测试文件`，把 76 份可选择的源文件按实际界面角色和上传入口重新组织为可直接选件的目录。

目录和配套文档必须让测试人员无需从 136 个混合格式文件中自行判断，便可明确：

- 登录什么角色；
- 在界面打开什么入口；
- 在本地进入哪个角色目录和分类目录；
- 选择哪一个源文件；
- 提交后由监检人员在哪些 R01–R69 节点核查；
- 异常文件如何补正并最终形成合格闭环。

## 2. 已确认边界

1. 采用实际复制，不使用符号链接，也不只提供索引。
2. 复制对象是 `document_catalog.json` 定义的 76 份逻辑源文件。
3. DOCX、XLSX、JPG以及原生 PDF 是可选择的上传源文件；DOCX/XLSX转换形成的同名 PDF 不重复复制。
4. 76 份逻辑源文件只在角色目录中分配一次；“重复”仅指角色目录中的副本与原始完整资料包并存。
5. 原目录 `files/R01-R69全节点业务验收测试包` 保持不变，原有 136 个文件、封包校验和与验证报告不受影响。
6. R01–R69 是监检人员的审查节点体系，不作为施工方和无损检测机构的本地目录主结构。
7. 施工照片没有 OCR 信息时可直接提交，由监检人员执行人工核验。
8. 建设单位、系统管理员和FDE工程师不上传工程业务资料，只建立操作说明目录。

## 4. 文件分配

### 4.1 测试控制资料：12份

以下文件仅供测试人员核对，不上传到工程业务节点：

`M00-README-001`、`M00-MASTER-001`、`M00-DIR-001`、`M00-SOURCE-001`、`M00-DATA-001`、`M00-SEAL-001`、`B00-QUALITY-001`、`V00-NODE-MATRIX-001`、`V00-REQ-MATRIX-001`、`V00-SOURCE-DIFF-001`、`V00-CHECKSUM-001`、`V00-REPORT-001`。

### 4.2 施工方：44份

施工方文件按主要业务用途分入十类目录：

| 目录 | 逻辑文件数 | 选件原则 |
|---|---:|---|
| `01_资质证照` | 1 | 施工单位及人员资质 |
| `02_设计资料` | 11 | 图纸、设计变更、计算分析和标准清单 |
| `03_施工方案` | 1 | 施工组织或专项方案 |
| `04_材料证明与复验` | 8 | 材质证明、复验、验收和代用审批 |
| `05_安全附件与阀门` | 5 | 阀门、安全阀、紧急切断阀和安装记录 |
| `06_焊接资料` | 7 | WPS、焊工资格、焊接台账和返修资料 |
| `07_热处理资料` | 2 | 热处理工艺和记录 |
| `08_防腐保温资料` | 2 | 阴极保护设备和测试记录 |
| `09_安装交工资料` | 3 | 安装、管线和交工记录 |
| `10_试验与吹扫资料` | 4 | 耐压试验、替代方案和最终确认 |

施工方测试人员不按 R 编号找文件，而是进入 `files/角色测试文件/02_施工方/<资料分类>` 选择源文件，再在“施工方工作台 → 项目文件库 / 施工资料台账”的对应类别上传。

### 4.3 无损检测机构：8份

无损检测机构目录包含机构与人员资质 1 份、底片与影像资料 3 份、检测报告 4 份。其余分类以说明文件指出界面内需执行的新增底片编号、批量导入记录、设备信息维护或问题补正操作。

测试人员登录无损检测机构角色后，从 `files/角色测试文件/03_无损检测机构/<检测分类>` 选择源文件，并通过“新增底片编号”“批量导入记录”“上传检测报告”“按节点挂载资料/提交检测资料”或“补正反馈”完成操作。

### 4.4 监检人员：12份

监检人员文件按实际上传节点分为 12 个 R 节点目录，每个目录一份：R21、R24、R28、R30、R44、R48、R49、R50、R51、R52、R53、R69。

测试人员登录监检角色，打开监检工作台相应 R 节点，再从 `files/角色测试文件/04_监检人员/<R节点目录>` 选择文件，通过“上传监检资料”补充现场照片、外部查询截图或 R69 评价记录。照片没有 OCR 信息时直接提交。

### 4.5 非上传角色

- 系统管理员目录只说明项目、组织、账号、成员、角色和节点权限初始化，不提供工程业务上传件。
- 建设单位目录只说明如何查看项目状态、节点摘要、报告和归档资料。
- FDE工程师目录只说明模型、规则、证据链和运行审计职责，不提供工程业务上传件。

## 5. “从哪里选择文件”的文档要求

根目录 `目录说明.md` 提供角色入口总览，至少包含：

| 界面角色 | 界面入口 | 本地选择根目录 | 是否选择业务文件 |
|---|---|---|---|
| 系统管理员 | 项目/组织/账号/权限管理 | `01_系统管理员_不上传业务资料` | 否 |
| 施工方 | 施工方工作台 → 项目文件库 / 施工资料台账 | `02_施工方` | 是 |
| 无损检测机构 | 无损检测机构工作台 | `03_无损检测机构` | 是 |
| 监检人员 | 监检工作台 → R01–R69节点 | `04_监检人员` | 仅12个节点 |
| 建设单位 | 项目查看/报告/归档入口 | `05_建设单位_只读` | 否 |
| FDE工程师 | 技术审计/规则/运行审计入口 | `06_FDE工程师_技术审计` | 否 |

三个上传角色分别建立 `上传清单.md`，测试控制目录建立 `文件清单.md`。每一份可选择的源文件必须独占一行，并包含：

1. 序号；
2. 逻辑文件编号；
3. 场景（基础项目或 S01–S06）；
4. 登录角色；
5. 界面入口或操作；
6. 本地选择目录；
7. 选择的源文件名；
8. 监检预期接收节点；
9. 用途和注意事项。

清单中的“本地选择目录”使用从 `files/角色测试文件` 起算的相对路径，文件名与磁盘实际名称完全一致。清单开头再给出一条可执行示例，例如：

> 登录“施工方” → 打开“施工方工作台 → 项目文件库 / 施工资料台账 → 设计资料” → 在本地打开 `files/角色测试文件/02_施工方/02_设计资料` → 选择清单指定文件 → 上传并关联清单所列审核环节。

`files/测试说明.md` 增加角色选件目录提示，指向 `files/角色测试文件/目录说明.md` 和各角色 `上传清单.md`，使界面操作说明与本地文件副本形成双向导航。

## 6. 复制和一致性规则

1. 以 `scripts/r01_r69_pack/data/document_catalog.json` 为唯一逻辑文件目录。
2. 原文件路径按 `outputSubfolder/fileStem.sourceFormat` 在完整资料包内解析。
3. 角色、分类和节点分配采用固定映射，不根据文件名临时猜测。
4. 使用保留文件时间和权限信息的常规复制方式生成副本。
5. 对每个副本计算 SHA-256，并与对应原文件比较；76 对必须全部一致。
6. 复制后检查逻辑编号、文件名、扩展名、数量和角色分布。
7. 不把上传清单、操作说明等 Markdown 文件计入 76 份业务/控制源文件。

## 7. 异常与闭环使用方式

角色目录保存的是首次上传使用的源文件副本，不因界面中的退回补正而修改或删除。测试时：

1. 按角色清单上传基础项目和 S01–S06场景源文件；
2. 按既定异常场景执行退回；
3. 从相同角色目录选择清单指定的补正、复检、返修或最终确认文件；
4. 以新版本或补充附件重新提交；
5. 监检人员在相应 R 节点复核并确认合格；
6. 最后在 R69完成质量保证体系实施状况评价。

## 8. 验证标准

生成后必须满足：

- `files/角色测试文件` 的既定目录全部存在；
- 76 份源文件均可由目录和清单定位；
- 分布严格为测试控制 12、施工方 44、无损检测机构 8、监检人员 12；
- 三个非上传角色目录不存在 DOCX、XLSX、JPG、PDF 等工程业务文件；
- 每份源文件仅分配到一个角色分类；
- 76 个副本与原文件的 SHA-256 全部一致；
- DOCX/XLSX转换生成的同名 PDF 未被误复制，原生 PDF 保留；
- 每份清单都明确登录角色、界面入口、本地选择目录和实际文件名；
- `files/测试说明.md` 能导航至角色选件目录；
- 原完整资料包仍为 136 个文件且原测试全量通过；
- Git变更仅包含角色目录、导航说明、设计和实施文档，不改写原始封包文件。
