# 监检工作台 AI 审查区域切换设计

## 目标

监检人员继续默认进入 `/workbench/inspection`。页面顶部项目区、左侧监检节点树和当前项目/节点上下文保持不变，只在右侧主内容区切换“AI 审查”和“审查列表”，默认显示 AI 审查。

## 范围

- 仅影响 `inspection` 角色的监检工作台。
- 前后端角色默认路径继续是 `/workbench/inspection`。
- 不修改后端审查接口、权限模型和三秒轮询策略。
- 旧 `/ai-review-b` 独立页面暂时保留，兼容历史链接。
- 施工方、无损检测机构、建设单位、管理员和 FDE 页面不变。

## 页面结构

`Workbench.vue` 继续作为唯一外层页面，负责：

- 顶部项目选择、待办、消息、文件预览和用户菜单；
- 左侧项目审核节点树；
- 当前 `projectId`、`nodeId` 和 URL 查询参数；
- “AI 审查/审查列表”区域状态。

右侧主内容区包含两个互斥区域：

1. `AI 审查`：默认区域，显示对话、执行轨迹、当前上下文、文件资料、快捷操作和人工结论。
2. `审查列表`：保留监检工作台现有总览、节点审计、资料、依据、AI 结果和人工审查内容。

切换按钮只改变右侧区域，不跳转路由，不重建顶部和左侧导航。

## AI 组件嵌入模式

现有 `ConversationalReviewWorkbenchB.vue` 增加嵌入模式：

```ts
interface Props {
  embedded?: boolean
  projectId?: string
  nodeId?: number
}
```

独立模式保持现状：自行加载项目列表和节点树，渲染自己的顶栏与左侧栏。

嵌入模式：

- 不渲染自身顶栏和节点树；
- 不调用项目列表和项目树接口；
- 使用父工作台传入的 `projectId/nodeId` 加载 AI 工作区；
- 父级项目或节点变化时清理旧节点瞬态数据并加载新节点；
- 不把路由替换成 `/ai-review-b`；
- 右侧对话与上下文区域保留。

## 区域状态与导航

新增区域状态 `ai | list`：

- 监检工作台首次进入、没有 `view` 参数时默认为 `ai`；
- `view=ai` 显示 AI 审查；
- `view=list` 显示审查列表；
- 切换时通过 `router.replace` 更新当前 `/workbench/inspection` 查询参数，同时保留 `projectId/nodeId/auditItem`；
- 浏览器刷新、前进和后退恢复对应区域；
- 选择左侧节点时保持当前区域；
- 点击项目总览时切换到审查列表，因为 AI 审查必须绑定具体节点。

## 状态保留

AI 区域使用 `v-show` 保留组件实例，切换到审查列表再返回时保留输入草稿、对话滚动位置和展开状态。本轮按用户要求不调整现有三秒轮询和流式连接行为。

## 测试

- 监检人员登录仍进入 `/workbench/inspection`。
- 无 `view` 参数时默认显示 AI 审查区域。
- 页面只出现一套项目选择和一套节点树。
- 点击“审查列表”后 URL 变为 `view=list`，右侧显示原审查内容。
- 点击“AI审查”后 URL 变为 `view=ai`，右侧恢复 AI 对话区域。
- 切换不改变当前 `projectId/nodeId`。
- 左侧切换节点后嵌入式 AI 区域加载新节点。
- `view=list` 刷新后保持审查列表。
- 其他角色页面和默认入口不变。

## 验收标准

- 监检页面整体框架不发生整页跳转。
- AI 审查是右侧默认内容，审查列表可在原位置切换查看。
- 项目和节点只有主工作台一个状态源。
- 独立 AI 历史链接仍可访问。
- 自动化测试、类型检查、生产构建和本地浏览器验证通过。
