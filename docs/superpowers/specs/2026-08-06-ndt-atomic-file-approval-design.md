# 无损检测原子资料单文件审批设计

## 1. 目标

在无损检测机构工作台补充原子资料类型上传入口，并允许每个上传文件独立提交审批。

本次保持现有无损检测节点编号 35–42，不进行全局业务规则重编号。上传完成后文件先保存为草稿；系统根据原子资料类型自动带出默认节点，用户可在提交前于 35–42 范围内调整；每个文件分别送审，不检查整包资料齐套性。

## 2. 明确边界

- 审批粒度是单个文件，不是资料大类、原子资料类型或上传批次。
- 一次可上传多个文件，但每个文件生成独立文档、独立草稿挂载和独立审批状态。
- 上传与提交分离；上传成功不自动送审。
- 单文件提交只校验文件存在、文件属于当前项目、至少关联一个 35–42 节点、挂载状态允许提交以及当前用户权限。
- 不校验其他资料是否存在，不计算或阻断整包齐套性。
- OCR 在上传完成后异步执行，但 OCR 排队中、识别中或失败都不阻断单文件提交。
- 原有底片编号登记、检测记录导入和检测报告专用上传继续保留。

## 4. 数据模型

复用现有 `DocumentAsset` 和节点 `Binding`，不新增资料包实体。

每个上传文件保存：

- `materialCategory: "无损检测资料"`
- `materialTypeCode`
- `materialTypeName`
- 当前文件版本、上传人、上传时间和 OCR 状态

上传完成后，为该文件和默认节点分别创建草稿挂载。多个文件不得共享挂载记录。文件的审批状态由自身挂载聚合：

- 所有挂载为草稿：`草稿`
- 任一挂载为需补正：`需补正`
- 存在已提交且无需补正挂载：`待审查`
- 所有挂载已通过：`已通过`

节点调整复用绑定更新能力，但仅允许草稿或需补正文件操作，且目标节点必须在 35–42。

## 5. 页面与交互

### 5.1 原子资料目录

将现有 7 个合并大类改为按 35–42 分组的原子资料目录。每行显示：资料类型、默认节点、已上传文件数和“上传资料”按钮。

页面不再显示“1/7 类已有资料”或大类“已覆盖”，避免产生齐套性暗示。顶部摘要改为草稿、待审查、需补正、已通过的文件数量。

### 5.2 上传抽屉

从原子资料行打开上传抽屉时，自动带入资料类型名称、代码和默认节点。上传抽屉允许调整本次文件的初始节点，范围仅限 35–42。

一次选择多个文件时，资料类型与初始节点相同，但上传完成后每个文件成为独立草稿。

### 5.3 文件审批列表

列表按文件展示：文件名、原子资料类型、关联规则、OCR 状态、审批状态、更新时间和操作。

草稿或需补正文件提供：

- `调整规则`：修改该文件的 35–42 草稿挂载。
- `提交审批`：只提交该文件当前可提交挂载。

其他状态不显示提交按钮。提交成功后只刷新该文件及相关节点状态。

### 5.4 原有专用流程

检测报告专用上传完成后，报告文件保存 `ndt_report` 类型并按单文件草稿方式进入列表；报告结构化业务记录继续保存报告编号、方法、比例、人员、结论和底片关系。

底片影像上传保存 `radiographic_film` 类型并进入单文件草稿列表。底片编号登记本身不是文件，不进入文件审批列表。

## 6. API 与权限

扩展通用上传会话文件上下文，允许保存 `materialTypeCode`、`materialTypeName` 和初始 `nodeIds`。完成上传后，为每个文档分别创建草稿挂载并返回文档与挂载 ID。

新增 NDT 专用单文件提交接口：

`POST /api/projects/{projectId}/ndt/material-submissions`

请求体：

```json
{
  "documentId": "DOC-001",
  "bindingIds": ["BIND-001"],
  "submitterComment": "提交质量保证手册审批"
}
```

接口要求 `ndt:submit`，并校验项目成员和节点范围。它不调用 `ndt_submission_readiness`，不读取其他文件，不检查 OCR 状态。成功后仅更新所选文件挂载，创建独立提交快照、监检待办和审计记录。

规则调整继续要求 `file:bind`，后端拒绝 35–42 之外的节点。

## 7. OCR 与审批

上传完成后继续调用现有文档解析任务。OCR 状态显示在文件列表中：排队中、识别中、已识别、人工修正或识别失败。

单文件提交不等待 OCR。OCR 完成后，AI 审查可以根据 `materialTypeCode` 使用相应字段模板生成缺项提示和证据定位；OCR 失败时显示“需人工核验”，不得自动退回或自动形成审批结论。

## 8. 错误处理

- 上传成功但挂载创建失败：文件保留在资料库，显示“未关联”，允许重新选择规则生成草稿挂载。
- 单个文件提交失败：只恢复该文件操作状态，不影响同批其他文件。
- 部分节点挂载不可提交：接口返回具体无效挂载 ID，不提交剩余挂载，避免部分成功造成歧义。
- OCR 失败：显示可重试状态，但提交审批按钮保持可用。
- 文件已提交：重复请求通过幂等键返回同一结果或明确提示已提交。

## 9. 测试与验收

### 后端

- 上传会话保存原子资料类型和默认节点，并为每个文件创建独立草稿挂载。
- NDT 用户只能把原子资料文件挂载到 35–42。
- 单文件提交只更新该文件挂载并生成一个审批待办。
- 缺少其他资料、OCR 排队中或 OCR 失败时仍可提交。
- 空挂载、跨项目文档、越权节点和已提交挂载被拒绝。

### 前端

- 原子资料目录完整显示上述 21 种类型。
- 点击上传自动带出资料类型和默认节点。
- 多文件上传后每个文件独立显示为草稿。
- 每个文件可独立调整规则、提交和显示审批状态。
- 页面不再显示资料齐套或大类已覆盖结论。
- 报告和底片影像仍可进入专用流程并出现在单文件列表。

### 页面验收

以 NDT 账号完成：上传两个同类型文件、分别调整规则、只提交其中一个、确认另一文件仍为草稿；在 OCR 排队中或识别失败状态提交文件；确认监检侧只收到已提交文件的待办。

## 10. 完成标准

- 原子资料入口、草稿挂载、规则调整和单文件审批形成完整闭环。
- 提交不受资料齐套或 OCR 状态阻断。
- NDT 节点范围严格保持 35–42。
- 后端契约测试、前端单元测试、类型检查和相关页面回归通过。
