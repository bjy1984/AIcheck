# 登录立即进入加载态设计

## 目标

用户点击“登录”按钮或在密码框按 Enter 后，登录表单必须立即进入提交状态，让用户清楚系统已收到操作，并防止请求期间重复提交或继续修改凭据。

## 范围

- 仅调整前端登录表单的提交状态，不处理本轮之外的后端登录性能问题。
- 提交开始后禁用用户名、密码、记住我、联系管理员重置和登录按钮。
- 登录按钮显示现有的 loading 动画。
- 表单校验失败、登录失败或提交过程抛错时恢复可操作状态。
- 登录成功后保持提交状态直至路由跳转完成。
- 同一提交状态内忽略后续点击和 Enter，确保最多只有一个登录流程执行。

## 实现设计

`LoginForm.vue` 使用单一的 `loading` 状态作为提交锁。`signIn` 在任何异步表单读取或校验之前检查并设置该锁；用户名和密码组件通过响应式 schema 属性接收 `disabled`，工具区控件与登录按钮直接读取同一状态。

登录流程改为可等待的顺序控制：表单校验通过后发送请求并完成用户态、动态路由和目标页导航；校验未通过或发生错误时退出。清理逻辑只在仍停留于登录页或提交失败时解除锁，从而避免成功跳转前按钮短暂恢复。

## 错误与边界处理

- 校验不通过：不发起网络请求，立即恢复表单。
- 接口失败或初始化失败：展示现有错误信息并恢复表单。
- 重复点击或重复 Enter：直接返回，不重复校验和请求。
- 首次修改凭据跳转：等待 `/change-password` 导航完成，保持提交态直到离开登录页。

## 测试

先增加失败测试，覆盖以下契约：

1. 提交入口在表单校验开始前进入 loading。
2. loading 时用户名和密码输入框被禁用。
3. loading 时工具区交互被禁用。
4. loading 时再次提交不会启动第二个登录流程。
5. 校验失败或登录失败后恢复可操作状态。
