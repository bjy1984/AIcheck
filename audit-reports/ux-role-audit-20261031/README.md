# 角色后台使用体验审计（2026-10-31）

审计对象：前端 `a01d4af8`（生产同版本）。方法：启发式评估 + 页面实测度量，一人评分。**不是用户测试**。

## 一、环境与局限（先看这个）

| 项 | 实际情况 |
|---|---|
| 环境 | 本机 vite 前端 + 本机内存版演示后端（同一份代码、演示种子数据）。**不是生产数据**。 |

| 看不到的 | 演示库里没有原件文件（预览报 NOT_FOUND），**原文预览与 OCR 字段对照没法实测**；文件选择器上传、报告生成、深色模式、移动端、生产量级数据（如储罐 8 的 65 条事实）没测。 |

## 二、评分口径

0–10 分，按「完成该角色的主要任务要多费劲」打：9–10 商业级（不用培训即可高效完成）；8 良好；7 可用且整体合理，有明显改进点；6 能完成但有摩擦；5 勉强；≤4 妨碍任务。

四个维度：**展示清晰性**（一眼看懂状态与含义）、**使用便捷性**（完成任务的步数与默认值）、**信息布局合理性**（重点信息与次要信息的位置与比重）、**反馈与容错**（出错、受阻、空状态时说得清不清）。

## 四、分角色证据

### 监检人员 6.9
做得好：
- 首页第一屏回答了「什么要我处理」：「1 项需要你处理」、全部 483 项的状态分布条（图例可点击筛选）、节点处理清单默认只看需处理。首页仅 1.4 屏。
- 受阻时说明原因：「正式审查存在前置阻断：仍有必传审查点缺少已确认资料证据，不能形成满足要求类结论」。
- 代码层：AI 面板对大量事实默认只展示 3 条、其余折叠（`FACT_PREVIEW = 3`），后端新增的 65 条标准引用事实不会铺满屏幕。

问题：
1. **节点页状态重复**：同一页里「AI 复核」出现 8 次、「未开始」7 次、节点标题 4 次（面包屑、标题、副标题、左树）。
2. **首屏被状态区占满**：可操作的「本节点所需资料」在 1440×900 下从第 524 像素（58% 处）才开始，之前依次是标题、步骤条、AI 复核说明、7 枚流程芯片、人工结论提示；1024×768 下约在第 650 像素（85% 处）。顶部步骤条是 sticky（约 100–120px），滚动时会压住下面的内容（实测 1024 宽下盖住了一行资料）。
3. **同一张卡里语气互相矛盾**：绿色「AI 已完成，等待人工确认」＋「证据不足」＋「AI 未形成任何发现」＋「AI 建议，未经人工确认」。
4. **人工结论默认值与规则冲突**：下拉默认「满足要求」，同时橙色提示「不能保存满足要求」。
5. **入口分叉**：待办消息 / AI 审查 / 重要节点审查 / 完整工作台四个标签 + 全局「一键分析」，用户要自己判断走哪条路；一键分析的作用范围（项目还是节点）看不出来。
6. 内部词外漏：`confirmed`、`Jev 看法 … 把握值（无理由，仅作提示）`、`R04`。
7. 节点 3.5–3.9 屏（1024×768）/ 2.6 屏（1440×900）；空状态占大卡片。
8. 1024 宽下节点处理清单的「状态」列被裁。

### 施工方 7.4（最好）
- 四段式单页：统一上传（拖拽）→ 监检意见 → 上传列表 → 分类指引；三个计数器；全是人话。
- 问题：计数矛盾要靠一段解释文字补——「待处理意见 0」同时「1 份文件标记为需补正」，页面写了三句话解释并让用户「联系监检人员确认」，用户走进死路。第四段分类指引表两列文字被截断；列表每行 5 个行内操作（查看/替换/提交/删除/选择环节）。

### 无损检测 5.8（最弱）
- **重点与次要倒置**：要处理的「监检反馈」（1 项待处理、截止 2026-06-28）在页面最底部，前面是 22 行资料类型上传表；整页 3.4 屏。顶部只有一个「监检反馈 1 项」数字，点不过去。
- 「业务规则」列前几行是同一句话，信息量近零；反馈编号 `NDT-FB-001` 直出；反馈表状态列与操作列在 1024 宽下重叠裁切。

### 建设方 6.9（低把握）
- 只读角色，页面简单：项目概况（总体进度、报告版本、归档资料）+ 节点进度表。
- 问题：三张 KPI 卡排成两列，第三张孤立、留白；「总体进度 0%」与下方多个节点已有状态并存，含义不清；页面里有 6 个表格节点（含隐藏），3.1 屏。

### 系统管理员 6.5
做得好：左侧「后台菜单」按 基础管理 3 页 / 规则与业务配置 6 页 / AI 知识库 10 页 / 运行与审计 3 页 分组，带页数；顶部全局搜索（⌘K）、任务中心；审计日志把「49 条已验证、1 条未经链校验」放在表格最上方。

问题：
1. **内部标识直接当内容**：`design_document`、`design_license`（物料审查点表）、`engineering-inspection-r01-v20260923`、`schema-review-v1.3`、`SecurityEvent`、审计日志里的 `拒绝 POST /v1/extension…`；「联调清单」页展示接口路径与字段名（`GET /api/workbench/projects`、`projects[].riskLevel`）——这是开发文档，不是管理员界面。
2. 菜单旁的小标签（复用、发布、打磨、对账、字段）含义不明。
3. 表格右侧操作列 sticky，1024 宽下盖住数据列；「归档/删除」挨在编辑旁，且合成一个控件。
4. 权限矩阵用「+17」收起权限，要点编辑才看得到。
5. DOM 里常驻 17 个 `el-table`（其余页签的表格没卸载），同屏可见只有 1–2 个。
6. 「知识库索引」状态列两行都空白。

### FDE 6.9（中低把握）
- 做得好：每页都有「推荐下一步」提示；治理总览把「阻断中心」按严重程度排序，点击进入对象；顶部有阻断 4 / 待审批 0 计数；低频指标折叠。
- 问题：**「成功率 100%（样本 1）」只有一张卡标了样本量**；采纳率、证据命中率也是 100% 却没写样本，容易误读；AI Run 页 5.1 屏，哈希串铺在中间；术语密（Run、Agent、Shadow、LiteLLM）；FDE 访问知识库页会被重定向回治理总览，我没看到任何提示（可能一闪而过，没截到）。

### 登录页（共用）
- 干净，有品牌区。但后端出错时（我这边一次是后端没起来）弹出原始英文「Request failed with status code 500」，**同一条在顶部提示和表单内各出现一次**；「记住我」默认勾选；没有自助重置密码，只有「联系管理员重置」。

## 五、跨角色共性

1. **信息架构强、页面排序弱**：导航、分组、计数、筛选都做得好；扣分主要在「一个页面里谁先谁后」——状态说明、流程芯片、解释文字挤在可操作内容前面。
2. **同一状态在多处重复展示**，而不是一处讲清。
3. **内部名词外漏**：监检端少量，管理员/FDE 端大量。
4. **表格在窄屏下挤压**（≤1100px）：sticky 操作列盖数据。1440 宽实测不裁。
5. **自动化检查是绿的，但检查的不是这些**：`audit:operability:static` 扫描 642 个文件 0 条发现；它不测信息排序和语气一致性。`audit:ui` 需要 Playwright 浏览器，本机未装，没跑。
6. **可维护性隐患**：`FdeConsole.vue` 28,538 行、`Workbench.vue` 10,482 行、`WorkbenchAiReviewPanel.vue` 2,208 行。单文件这么大，改一处体验容易牵动别处，也是上述不一致的成因之一。

## 为什么到不了 9，以及怎么到

我没有为了凑数把分打高。剩下的差距是这些，都不是改几行样式能解决的：

1. **监检节点页的流程结构**：「待办消息 / AI 审查 / 重要节点审查 / 完整工作台」四个入口并存，用户仍要自己判断走哪条路；步骤条、流程状态条、AI 卡、人工卡四层都在讲「现在到哪一步」。要降到一层，需要产品先决定哪些入口合并——这是产品决定，不是前端修补。
2. **原文预览与 OCR 字段对照**：演示库没有原件，这轮仍然没法实测，而它正是监检人员「看着原文核对」的核心动作。没验证就不能给高分。
3. **生产量级数据**：全部是演示数据下的评分。65 条事实、几百个节点时的表现没看到。
4. **管理员/FDE 的技术标识**：版本串、Prompt 键、schema 名是配置的本体，不能简单隐藏；折叠进「技术详情」需要按页设计。
5. **无用户参与**：9 分的口径是「不用培训即可高效完成」，这个只能靠真实用户做任务测试，我一个人打不出来。
6. **没重测的**：1024 宽下的表格裁切（操作列吸附盖住数据）本轮没处理；FDE 另外 9 页、知识库另外 9 页没看。
