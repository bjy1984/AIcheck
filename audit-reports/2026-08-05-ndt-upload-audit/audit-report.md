# 无损检测机构资料上传页面审查

审查范围：无损检测机构工作台中的标准资料清单、通用资料上传抽屉、检测报告专用上传抽屉，以及前后端提交就绪校验。

结论：当前页面能够完成文件上传、报告字段录入和 RT 底片关联，但尚不能按 R23–R30 准确判断资料齐套。主要风险是资料大类粒度过粗、旧规则编号未迁移、任意一个文件即可让整类显示“已覆盖”，且最终提交只校验报告与底片，不校验其余工作见证。

## 规则覆盖结论

| 规则 | 当前覆盖 | 主要缺口 |
| --- | --- | --- |
| R23 | 部分覆盖 | 缺少质量保证手册、质量体系实施记录的独立资料项；受控记录表格与受控报告表格未拆分；设备检定资料未正确关联到 R23。 |
| R24 | 基本覆盖 | 有“无损检测方案”，但通用上传没有资料类型、方案编号、方法、比例、批准人、标准编号等结构化字段。 |
| R25 | 部分覆盖 | 无不合格品/不符合项控制程序的独立资料项；无问题时直接显示“已覆盖”；委托单、联络单/意见书、反馈见证不能形成一条问题闭环。 |
| R26 | 部分覆盖 | 缺少无损检测人员明细表、必要时劳动合同证明；证书与人员、项目任命、检测方法之间不能逐人关联。 |
| R27 | 基本覆盖 | 已列单项工艺文件和操作指导书，但两者未拆分，也没有工艺编号、方法、设备、灵敏度、验收等级等字段。 |
| R28 | 部分覆盖 | 有检测记录与报告入口；报告专用表单缺少焊口编号和签章状态，提交不要求检测记录存在或与报告关联。 |
| R29 | 不充分 | 登记一个底片编号即可使类别显示“已覆盖”；未校验所有 RT 底片影像均已上传、底片与报告逐一对应，也未校验影像文件实际存在。 |
| R30 | 不充分 | 没有“是否委托外部检测”条件及委托检测合同；现场抽查底片、记录、报告未形成专门资料包；缺少抽查批次/对象关联。 |

## 高优先级整改

1. 把 7 个大类改成“资料大类 + 原子资料类型”两层结构，至少新增质量保证手册、受控记录表格、受控报告表格、质量体系实施记录、人员明细表、劳动合同证明、不合格品控制程序、联络单/意见书、处理反馈见证、检测委托单、委托检测合同、现场抽查记录等类型。
2. 将页面所有无损检测规则引用从旧 R35–R42 迁移为现行 R23–R30，并按资料项准确关联，移除无关的 R65。
3. 齐套状态按原子资料项判断，不得以同一大类下存在任意文件判定整类“已覆盖”；增加“不适用/待判定/待上传/部分齐全/已齐全/需补正”。
4. 最终提交校验应覆盖适用的 R23–R30 资料项，而不是只校验检测报告、OCR、RT 比例与底片关联。
5. 增加条件逻辑：是否发生不合格/不符合项、是否采用 RT、是否委托外部检测、是否需要劳动合同证明；条件成立时动态生成必传项。
6. RT 校验应做到每份报告关联具体焊口和底片、每个底片编号存在影像文件、提交范围覆盖本批次全部应检底片；现场抽查资料应独立成包。

## 交互与可访问性观察

- 优点：页面按资料类别给出缺口提示；报告表单提供检测方法、比例、标准、人员、结论及底片关联；表单标签和关闭按钮在 DOM 中可识别。
- 风险：通用上传抽屉只有文件选择，没有具体资料类型和关键元数据；大表格在 1280px 视口发生横向裁切，重要的状态和规则列不易同时查看；无问题时“问题处理闭环”显示已覆盖会产生错误的完成感。
- 截图不能验证键盘遍历顺序、焦点可见性、屏幕阅读器播报、色彩对比数值和错误提示的动态播报，需要另做交互测试。
