# UX 细节审计 · 商业级标准（2026-08-12）

环境：线上 `http://39.108.65.148:8081`，监检人员视角，节点 24（焊工资格证）——
这是 demo 数据里唯一有完整 AI 运行记录与人工结论的节点。

判定标准：**商业级** = 用户不需要理解系统内部实现，就能在最少的操作里拿到判断
所需的全部信息。不是"功能有没有"，而是"用起来累不累"。

## X-1 · 文件预览与 OCR 字段被上下切开 【P1·核心体验】

`FileDetailDialog.vue` 的实际布局：

```
ElDialog (960px)
├── file-layout  (grid: 1.7fr | 0.9fr)
│   ├── preview-shell   ← 预览（min-height 仅 168px）
│   └── detail-side     ← 文件状态 / OCR状态 / "0 字段 · 0 片段 · bbox 0%" / ParseResult / 版本 / 大小 / 绑定数
├── 历史版本   ElTable height=150
├── OCR 字段   ElTable height=160   ← 字段内容在这里
└── 证据定位   ElTable height=150
```

**问题**：右侧 `detail-side` 有 260px 以上的宽度，却只放了 7 行元数据，其中
「OCR 产物」一栏只给了 `0 字段 · 0 片段 · bbox 0%` 这种**计数**。真正要看的
「证书编号 = TS6J-2024-03158」在预览**下方**，需要滚动，且和预览无法同屏对照。

监检人员的核心动作是**「看着原文核对字段」**——这个动作现在要求他上下滚动，
在 168px 高的预览和 160px 高的表格之间来回找。

**商业级做法**：右侧改为字段列表（可滚动），点击字段时预览跳转到对应页并高亮
bbox。元数据折叠进一个次级面板。

## X-2 · 有 bbox 数据却没有可视化高亮 【P1】

后端在 bbox 上投入很重：
- `ocrReadiness.bboxCoverage` 是就绪度指标之一；
- R19 的 LLM 输出校验**强制要求 bbox 必填**（审计第二轮确认过）；
- `EvidenceLocatorDialog` 拿得到 `pageNo` 与 bbox。

但前端**一处都没有把 bbox 画出来**：

```
grep -cE "bbox|boundingBox|highlight-box|overlay" EvidenceLocatorDialog.vue
→ 0
```

预览用的是 `<img>` / `<iframe>` 直接内嵌，没有任何覆盖层。用户看到「证据引用：
TS6J-2024-03158，第 1 页」，但要自己在整页 PDF 里找这行字在哪。

**这是投入产出严重不匹配的一处**：后端为可定位性付出了完整代价（强制 bbox、
覆盖率指标、就绪度门禁），前端把这份能力浪费了。

**商业级做法**：预览层上叠一个绝对定位的高亮框，点证据链条目即滚动到该页并闪烁
定位。这是合同/票据类审查产品的标配。

## X-3 · 主工作台的 AI 推理过程无折叠，7 步全展开 3.1 屏 【P1】

线上实测（节点 24，1280×720）：

```
主滚动容器高度 1917px / 可视 625px  →  需滚 3.1 屏
.el-collapse 数量: 0
```

「二、AI 审查执行过程」把 7 个步骤全部平铺展开，每步含 输入 / 反馈 / 工具标签 /
证据引用四块：

```
1 读取项目和节点上下文     完成    输入: 24.焊工资格证…  反馈: 华东成品油…  T01
2 定位业务规则与资料要求    完成    输入: R24            反馈: 已加载4项…    T01 T02
3 检索项目文件与证据链     完成    …                                    T02
4 抽取 OCR 字段和结构化信息 完成    输入: 0个字段         反馈: 暂未返回…     T03 T04
5 执行规则核验            完成    …                                    T07 T08
6 生成缺项与人工确认项     需人工确认 …                                  T11
7 证据链与结论回写         完成    输入: AIRUN-…        反馈: 需人工确认/置信度50%  T12
```

**问题**：监检人员最需要的是第 7 步的结论（需人工确认 / 置信度 50%）和第 6 步的
缺项（姓名、有效期、持证项目），但这两条在**最底部**，要滚 3 屏才看到。前 5 步
（读上下文、定位规则、检索文件）是过程性信息，日常不需要看。

对照：AI 复核 **B 版**工作台（`ConversationalReviewWorkbenchB.vue`）做对了——
默认折叠、`<button>` + `aria-expanded`、spinner/✓ 状态、chevron 旋转、展开后带
进度条与事件时间线。**同一产品里两套标准。**

**商业级做法**：结论与缺项置顶成卡片，执行过程默认折叠为一行摘要
（「7 步已完成 · 展开查看」），与 B 版对齐。

## X-4 · 工具编号 T01–T12 直接暴露给业务用户 【P2】

每个步骤下方挂着 `T01` `T02` `T07` `T08` `T11` `T12` 这样的标签，没有任何图例或
悬浮说明。监检人员不知道 T07 和 T08 是什么，也无从判断它们是否该出现。

这与已修的 U-3（施工方看到「OCR 中 / 切片中 / 向量化中」）是同一类问题——
**技术标识泄漏到业务界面**，只是这次在监检侧。

**商业级做法**：要么换成业务语言（「查焊工持证范围」），要么去掉，要么悬浮显示
工具全名与用途。

## X-5 · 未选择节点时渲染出一整屏「假内容」 【P2】

带 `?nodeId=24` 直接访问时节点未被选中，页面渲染出完整骨架：

```
未选择节点
审计项 7 项
  1 资料提交  -  ● 状态待加载
  2 OCR 抽取  -  ● 状态待加载
  …（七项全是 - 和「状态待加载」）
监检依据 · 资料提交
  规则编号 -   来源 -   类别 -   业务模块 -
```

七个步骤、四个字段全是 `-`，但版式与真实内容**完全一致**。用户会以为"这个节点
没数据"，而不是"我还没选节点"。

**商业级做法**：未选节点时给一个明确的空状态（图示 + 「请从左侧选择审查节点」），
不要渲染带占位符的完整骨架。

---

## X-6 · 表格高度写死，信息被压在 150–160px 里 【P2】

`FileDetailDialog` 三个表格分别写死 `height="150"` / `160` / `150`。在 960px 宽的
弹窗里，一份有 20 个 OCR 字段的证书，用户要在 160px 的窗口里滚动查看——
而弹窗下方还有大片空白。

同样问题在 `ElDialog width="960px"`：现代显示器普遍 ≥1440px，弹窗却固定 960px，
右侧详情栏被挤到 260px。

**商业级做法**：弹窗宽度用 `min(1400px, 90vw)`，表格高度改为 `flex: 1` 自适应。

## 优先级建议

按「监检人员每天要做多少次」排序：

1. **X-1 + X-2**（预览与字段同屏 + bbox 高亮）——核对字段是核心动作，一天做几百次；

## 线上验不了的部分，以及为什么

**bbox 高亮框画不出来**，因为线上与 demo 数据里 `evidence_links.bbox` 全为空，
文档也没有真实字节（`storageUnavailable: true`，MinIO 未部署）。

所以没有靠「点开看看」交差：把几何换算抽成 `frontend/src/utils/bboxHighlight.ts`
并补了单测（前端测试文件 6 → 7），把「零宽/反向框拒绝」「尺寸未知返回 null」
「百分比而非像素以跟随缩放」这些行为钉死。抽出来还消除了弹窗内联实现与共享实现
漂移的可能。

**PDF 仍然只能跳页、不能画框**。浏览器原生 viewer 的内部布局与缩放不可控，要画框
必须引入 pdf.js 自行渲染到 canvas，属独立技术选型，不在本次范围。提示条如实说明
当前定位到了什么程度，不含糊其辞。

## 线上验证过程中发现并修掉的三处

都是「本地看不出、线上才现形」的：

1. **X-5 原本只做了一半**——空状态出来了，下方「监检依据 · 资料提交」仍在渲染
   `规则编号 -／暂无配置` 的完整骨架，正是这条要消灭的东西。连带漏掉「上传监检资料」
   「AI审查」两个按钮和目录状态错误横幅。
2. **摘要把「待执行」算成「需关注」**。状态词表是 待执行/执行中/完成/异常/需人工确认，
   只有后两个是需关注。AI 尚未运行时七步全是「待执行」，摘要报「7 步需关注」——
   这等于教用户忽略这个提示。改为三类语义后实测：未运行显示「7 步 · 尚未运行」，
   跑完显示「7 步 · 1 步需关注：生成缺项与人工确认项」。
3. **定位条目缺 `aria-pressed`**。选中态原先只有视觉类名，读屏器读不出当前定位在哪一条。

## 顺带修掉的部署脚本隐患

`deploy_to_server.sh` 里 `$COMMIT）` 的全角括号在某些 locale 下会被 bash 并入变量名，
`set -u` 直接报 `unbound variable`。已给紧邻中文的变量全部加花括号。
这类 bug 平时不发作，一旦发作就是部署中断。
